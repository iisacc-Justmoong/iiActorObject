# GLB 메시의 원본 점 식별 정보

`exportObject3DGlb`는 본체의 편집 토폴로지가 있는 메시마다 표준 GLB의 표시 정점과 함께 선택적인 iiActorObject 원본 점 식별 정보를 기록한다. `importObject3DGlb`는 이 정보가 유효하고 현재 표시 데이터와 양립할 때 이음새와 재질 경계에 나뉜 표시 정점을 같은 본체 제어점으로 다시 연결한다. 점과 스킨·모프는 iiActorObject 엔진이 소유하며 `NSCharacter`는 해당 에셋을 참조한다.

GLB 출력 내부에서 표시 정점 속성, 점 식별 속성 및 메시 메타데이터 기록은 별도 처리기다. 입력 메시와 본 배열을 소유하지 않으며 호출자가 출력 버퍼의 수명과 실패 시 폐기를 담당한다. 이 처리기들은 기존 SDK 라이브러리에 포함되는 내부 객체 타깃이다.

## 교환 계약

- 각 프리미티브의 `_IIACTOROBJECT_POINT_ID` 속성은 정규화하지 않은 `UNSIGNED_SHORT` `VEC2`다. 첫 성분은 원본 제어점 ID의 하위 16비트, 둘째는 상위 16비트다. 이는 표준 메시 렌더링 속성을 대체하지 않는 앱별 속성이다.
- 메시 `extras.iiActorObjectPoints`에는 `version: 1`과 이진 `bufferView` 인덱스가 있다. 이 뷰에는 사용되지 않는 원본 점의 ID와 double 정밀도 위치, 스킨 영향, 해당 점의 논리 모프 위치 변화, 빈 스킨 행, 모프 이름과 본 이름이 저장된다. 표시 정점의 위치·스킨·모프는 GLB 표준 데이터에서 읽는다.
- 이진 뷰는 `iiGLPT\0\0` 8바이트 서명과 일곱 개의 리틀엔디언 32비트 정수 `version`, `pointCount`, `targetCount`, `unusedCount`, `unusedMorphCount`, `emptyWeightCount`, `boneCount`로 시작한다. 이어 모프와 본의 이름이 각각 길이와 UTF-8 바이트로 저장된다. 사용되지 않는 점에는 ID, 세 개의 IEEE 754 64비트 좌표, 영향 수와 본 ID·64비트 가중치가 이어진다. 그 뒤 사용되지 않는 모프의 점 ID·대상 ID·64비트 좌표 세 개, 빈 스킨 행의 점 ID 순서다.
- 가져오기에서는 모든 표시 인스턴스의 위치·스킨·위치 모프 값이 정확히 일치할 때만 같은 ID로 연결한다. 프리미티브 인덱스가 사용하지 않는 중복 속성 행은 같은 ID의 표시 인스턴스가 있으면 비교에서 제외한다. 사용되지 않는 점에는 동일한 노드 또는 스킨 기준 변환을 적용한다. 일반 GLB에서는 모프 이름과 스킨 관절 이름·순서가 저장된 값과 다르거나 ID·형식·크기·영향 수가 유효하지 않으면 메타데이터를 적용하지 않는다.
- [외부 편집용 작업 정보](GlbExternalEdits.md)와 각 관절의 완전한 원본 본 번호가 있으면 이름과 스킨 관절 순서 대신 그 번호로 보조 자료의 가중치를 연결한다. 관절 번호가 불완전하면 기존 이름·순서 검사를 적용하며 자동 외부 편집 병합은 별도로 거부한다. 모프 이름은 여전히 저장된 이름과 일치해야 한다.
- GLB 문서의 구조가 유효할 때 메타데이터가 손상되었거나 같은 ID의 표시 인스턴스가 서로 다르게 편집된 경우에는 경고하고 표준 GLB에서 읽은 점들을 유지한다. 식별 속성만 남고 메타데이터가 제거된 경우에도 식별 속성을 무시하고 경고한다. 모프 이름 변경이나 식별되지 않은 관절 이름 변경 후에는 사용되지 않는 점의 보조 자료를 추측해 재연결하지 않는다. 반면 버퍼 뷰가 파일 범위를 벗어나는 등 GLB 구조 자체가 유효하지 않으면 보조 자료 복원 이전에 파일 전체의 가져오기를 거부한다.
- 원본의 빈 스킨 행은 표준 표시 메시에서 루트 본의 가중치 1로 대체한다. 다시 읽을 때 그 표시 가중치가 그대로이면 빈 원본 행으로 되돌리고, 다른 본이나 가중치로 바뀌면 변경된 값을 사용한다. 외부 편집자가 의도적으로 빈 행을 같은 루트 가중치 1로 바꾼 경우는 대체값과 구별할 수 없어 빈 행으로 복원된다.
- 보조 뷰는 최대 256 MiB다. 내보내기에서 이 한도를 넘으면 예외를 내고 GLB를 생성하지 않는다. 가져오기에서는 기존 `GlbImportOptions`의 원본 정점·모프·모프 델타·본·정점당 영향 수 한도와 파일 전체 예산도 적용한다. 가져오기 한도를 초과하면 표준 점으로 되돌리고 경고한다. 이 자료는 무결성 인증 수단이 아니며 외부에서 변경하거나 제거할 수 있다.

## 범위와 제한

원본 점 식별정보의 바이너리 기록·판독은 메시 및 본 자료만 받는 내부 객체 타깃으로 분리되어 있다. 디코더는 손상된 자료와 크기 한도를 확인한다. 표준 메시·스킨·모프와의 비교와 원본 점 재연결은 입력을 변경하지 않는 별도 복원 계획기가 담당한다. GLB 어댑터가 메타데이터와 본 대응을 해석하고, 계획이 성공했을 때만 가져오는 메시와 예산에 반영한다. 이 내부 타깃은 별도 설치 패키지가 아니며 앱은 기존 공개 교환 API를 사용한다.

일반 GLB 소비자는 사용자 정의 속성과 `extras`를 보존할 의무가 없다. 따라서 이 계약은 그 자료가 남고 일관성을 만족하는 SDK 재가져오기에만 적용된다. 모든 외부 편집기에서의 점 ID 보존을 보장하지 않는다. 표준 GLB 표시 위치·모프는 float 정밀도다. 원래 사각형, 숨김 폴리곤, 별도 원본 layout·UV·법선 ID, 같은 이름으로 통합된 모프의 개별 원본 레코드 ID와 편집 이력은 복원하지 않는다. 이런 자료는 본체 프로젝트 또는 해당 FBX 저작 메타데이터에 보관해야 한다.

표준 메시를 변경하는 앱이 같은 점의 표시 인스턴스를 모두 일관되게 편집하면 그 값을 사용한다. 일부만 바꾼 경우는 별개의 편집으로 보존하며, 사용되지 않는 점을 나중에 표시하도록 토폴로지를 바꾸면 저장된 식별 정보와 충돌할 수 있다. 실제 CC5·Blender·Unreal 앱과 화면 표시의 검증은 수행하지 않는다.
