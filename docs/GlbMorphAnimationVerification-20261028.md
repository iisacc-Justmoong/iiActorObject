# GLB 모프 애니메이션 검증 — 2026-10-28

## 범위

코어 `exportObject3DGlb`의 명시적 모프 오버로드와 이를 전달하는 `NSCharacter::exportGlb` 오버로드를 추가했다. 곡선을 이름 또는 명시적 메시·모프 대응으로 연결하고, 각 메시의 서로 다른 키 시간 합집합에서 선형 보간한 전체 모프 가중치 배열을 glTF `weights` 채널로 기록한다. 원본 에셋과 클립은 변경하지 않는다. 기존 오버로드의 스칼라 곡선 거부와 명시적 폐기 정책은 유지한다.

## 결과

- macOS arm64 Release의 코어 전용·NSCharacter 포함 구성을 C++23으로 빌드했고, 두 구성에서 GLB 애니메이션의 네이티브 검증과 독립 판독 테스트가 각각 통과했다. 원본 클립과 같은 Skeleton, 변형 바인드 제한, 비유한·float32 범위 및 시간 충돌, 매핑 충돌과 누락, 출력·키·매핑 예산, 빈 애니메이션 거부를 검사했다.
- 독립 판독기는 다른 시간 키를 가진 세 곡선과 두 메시에서 메시별 `weights` 입력·출력 배열을 읽고 키 사이의 표본 및 모프 적용 위치를 원본 선형 곡선과 비교했다. 한 곡선을 여러 모프에 연결하는 경우, 같은 이름의 모프를 메시별로 다른 곡선에 연결하는 경우, 본 트랙과의 조합 및 정적 메시의 모프 전용 클립을 확인했다. 수치 비교 허용치는 `2e-6`이다.
- 별도의 생성 캐릭터 fixture에서는 얼굴과 혀에 같은 `jawOpen`·`tongueOut` 곡선이 기록되는지 읽었으며, NSCharacter 편의 오버로드의 바이트가 코어 결과와 같음을 확인했다.
- 코어의 선형화 스냅샷 GLB 2개, FBX 애니메이션 2개와 GLB 탄젠트 독립 검사 1개가 통과했다. 첫 회귀 실행에서 기존 FBX·탄젠트 테스트 실행 파일 세 건이 `SIGTRAP`으로 종료되었다. 당시 실행 파일은 현재 라이브러리보다 오래되었으며, 해당 테스트 대상을 다시 빌드한 후 세 건 모두 통과했다. 신호 종료의 세부 원인은 확정하지 않았다.
- 프로젝트 `build/`에 별도로 설치한 코어 전용과 NSCharacter 포함 소비자에서 새 공개 API를 빌드하고 테스트했다. 사용자 전역 설치본은 변경하지 않았다. 기존 GLB 출력 심볼과 새 오버로드가 모두 존재하며, 직접 동적 의존성에 Qt는 나타나지 않았다.
- 새 API 테스트는 구현 전 미선언 오류를 확인한 뒤 구현 후 통과했다. 설치 소비자 테스트 코드의 중복 지역 변수는 수정하고 다시 빌드하여 통과했다.

사용자 지시에 따라 CC5·Blender·Unreal 등 실제 앱은 실행하지 않았다. 형식 구조와 수치 검사는 대상 앱의 가져오기·슬라이더 연결이나 제작용 표정 품질을 입증하지 않는다.
