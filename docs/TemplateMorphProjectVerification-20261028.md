# 템플릿 모프 리그 프로젝트 검증 — 2026-10-28

## 저장과 재생성

합성 몸·의상 템플릿에서 `height=0.25`, `body_width=0.2`를 기준으로 두 개의 `height` 끝점을 모프 리그로 베이크했다. 기준 입력에 포함된 다른 조절도 저장한다. 저장 전 기존 동명의 모프를 명시적으로 교체하고 `epsilon=1e-12`을 사용했다. 기준 템플릿에는 이 임계값보다 작은 점 변위를 넣어, 기본 임계값 0으로 재생성하면 기록되는 점이 달라지는지 별도로 확인한다.

버전 21 프로젝트를 다른 본체 엔진에 복원한 뒤 저장된 템플릿·기준 입력·채널 끝점·베이크 설정으로 다시 생성했다. 두 메시의 기준 점과 모프 이름·원본 점 ID·변위를 비교하였다. 복원 리그를 런타임 액터에 적용한 결과도 템플릿의 목표 형상과 비교했다. 편집 이력의 undo·redo와 포즈 리그의 혼합 복원도 확인한다.

같은 설정을 공유하는 두 리그를 각각 다른 가중치로 평가하고 서로 다른 액터에 적용해 결과가 섞이지 않는지도 검사한다.

관절 두 개의 원본 ID와 당시 이름은 원본 ID 순서로 보존한다. 대상 에셋의 자식 관절 이름을 바꾸고 리그를 재연결한 뒤 프로젝트를 다시 저장해도 샘플 당시의 ID·이름 기록은 그대로이며, 복원된 대상 에셋에는 바뀐 이름이 남는다. 이 출처는 현재 재연결 대상에 대한 새 관절 매핑이 아니다.

## 원본이 없거나 입력이 손상된 경우

원본 템플릿을 명시적으로 제거한 뒤 저장하면 리그와 알려진 기준 입력·베이크 설정은 남고 원본 참조는 없는 상태로 복원한다. 직접 구성한 리그에서 기준 입력과 설정을 제공하지 않은 경우는 각각 `nullopt`로 유지한다. 임의 사용자 드라이버가 같은 형식 이름을 주장하더라도 내장 드라이버로 인정하지 않는다. 256개를 넘는 선택 리그는 내보내기에서 거부한다.

독립 Python 파서는 버전 21 헤더·CRC, 공유 프로그램 테이블, 기준 입력, 비기본 베이크 설정, 채널과 원본 관절 ID·이름, 원본 템플릿 참조를 읽는다. CRC를 다시 계산한 범위 초과 입력, 상충하는 기준값, 손상 설정, 잘못된 소스 참조, 중복·불일치 관절 ID와 메시 이름 등 25개 손상 사례는 거부된다. 실패 후 기존 에셋과 자원 개수뿐 아니라 다음 에셋 ID도 유지하는지 검사한다. 전체 기준 입력이 없지만 원본 템플릿이 남은 유효한 파일은 별도로 복원한다.

## 실행 결과

최종 소스에서 표준 구성의 프로젝트·기존 버전·FBX 작성 탄젠트 묶음 34개와 NSCharacter를 제외한 코어 구성의 관련 묶음 32개가 통과했다. 모프 프로젝트 5개 검사는 표준, 코어 전용, DNA와 NSCharacter를 모두 제외한 구성에서 각각 통과했다. 템플릿 맞춤·소유권·모프 4개 검사는 표준과 코어 전용에서 각각 통과했다.

DNA와 템플릿 모프 리그를 섞은 프로젝트 검사를 포함한 DNA 저장·복원 묶음은 표준과 코어 전용에서 각각 3개가 통과했다. 빌드 내부에 별도로 설치한 표준·코어·VisualCodec 소비자 검사 3개도 통과했다. CC0 인체 템플릿의 얼굴과 FBX·GLB 독립 파일 검사 4개가 통과했다. 이 검사는 해당 표본과 형식 경로의 근거다.

AddressSanitizer와 UndefinedBehaviorSanitizer를 켠 모프 프로젝트·템플릿 검사 9개도 통과했다. 이 환경에서 누수 검출은 꺼 두었으므로 누수 검사를 통과했다는 뜻은 아니다.

## 범위

표준·NSCharacter 제외·DNA와 NSCharacter 제외 구성에서 공용 프로젝트 기능을 검사한다. DNA 리그와 모프 리그의 혼합 프로젝트는 독립 DNA fixture와 native reader로 검사한다. 프로젝트는 원본 입력과 결과 에셋을 보관하지만 외부 앱의 제어기를 생성하지 않는다. CC5·Blender·Unreal 실행과 시각 품질은 사용자 지시에 따라 검사하지 않는다.
