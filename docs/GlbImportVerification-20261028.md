# 편집 가능한 GLB 자산 입력 검증 — 2026-10-28

## 범위

공용 `importObject3DGlb`와 비소유 `NSCharacter::importGlb`를 추가했다. 지원 형식과 손실·거부 경계는 [GLB 자산 입력 계약](GlbImport.md)에 기록한다. 이 검사는 전체 캐릭터 엔진이나 앱 호환성의 완료를 뜻하지 않는다.

## 네이티브 및 형식 검사

- 구현 전 새 API를 사용하는 테스트의 미선언 컴파일 실패를 확인했다. macOS arm64 Release에서 코어 전용 구성의 `glb_import.roundtrip`, `glb_import.validation` 2건과 NSCharacter 포함 Ninja 구성의 같은 2건이 통과했다. 해당 Ninja 구성은 DNA를 끄고 빌드했다.
- 자체 GLB 출력과 별도로 손으로 구성한 GLB를 읽어, 관절 순서가 부모 우선이 아닌 스킨의 인공 루트·원본 관절 대응과 사용되지 않는 원본 점을 확인했다. 여러 프리미티브와 소재, UV 세트, 양자화 점, 희소 모프, 반사·비균일 스케일, 공통 기준 변환과 12개·80개 영향 가중치를 검사했다. 골격·모프 변형 수치를 원본과 비교하고 가져온 원본 점·관절의 편집과 되돌리기를 검사했다.
- 임베디드 PNG, UV별 기본색·노멀 연결과 호스트 이미지 해석기, 요청·바이트 상한을 검사했다. 탄젠트와 사용 중인 `OPAQUE` 텍스처의 손실은 기본 거부하며 명시적 허용 시 경고한다. 사용되지 않은 GLB 소재·텍스처·이미지도 경고한다.
- 잘못된 관절·가중치·역 바인드·shear·회전·노드 중복, 지원하지 않는 속성·애니메이션과 예산 초과를 거부하는지 확인했다. 512건의 결정적 바이트 변형에서는 제한된 예산과 엔진의 자산 수를 검사했다.
- 테스트와 가져오기 소스를 ASan·UBSan으로 직접 컴파일한 정상·오류 검사가 통과했다. 이 직접 검사에서 기존 iiActorObject 동적 라이브러리와 iiJson·ufbx는 계측하지 않았다. 최초 실행에서는 계측된 테스트가 `clear()`한 용량 보유 벡터를 비계측 라이브러리가 다시 채우는 사례에서 컨테이너 경계 오류가 보고되었다. 새 빈 벡터로 바꾼 재검사는 통과했으나 전체 라이브러리를 계측한 검사는 아니므로 최초 보고의 근본 원인을 확정하지 않는다.
- 변형 테스트의 첫 자산 수 비교는 엔진이 참조가 사라진 기존 자산을 새 생성 시 자동 정리하는 동작을 고려하지 못했다. 기준을 재기 전에 자동 정리를 수행하도록 고쳤다. 첫 `OPAQUE` 테스트는 사용 중인 소재가 아니라 미사용 소재를 변경한 fixture 오류였으며, 사용 중인 소재로 수정하고 미사용 자원 경고를 추가했다.

실제 CC5·Blender·Unreal 또는 사용자용 명령행 도구는 실행하지 않았다. 제작용 GLB, 다른 플랫폼, 애니메이션 입력, 여러 스킨과 최종 외형 품질은 이 결과로 입증되지 않는다.
