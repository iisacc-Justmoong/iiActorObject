# 노멀 맵 연결 검증 — 2026-10-28

이 기록은 [노멀 맵](NormalMaps.md)의 데이터·편집·파일 교환 경계에 한정하며, 캐릭터 생성·편집 전체 목표의 완료를 의미하지 않는다.

## 확인한 내용

- 합성 이미지 두 개와 서로 다른 UV 순서의 메시 두 개를 사용하여 기본 색상과 노멀 맵이 서로 다른 UV를 참조하는 경우를 검사했다. 독립 Python 파서는 GLB의 `normalTexture`, UV 번호, 이미지 참조와 강도를 검사했다. 다른 독립 파서는 FBX의 `NormalMap` 연결, UV 세트, 내장 PNG 바이트와 전용 강도 속성을 확인했다.
- 별도로 작성한 ASCII FBX 입력을 가져와 노멀 맵을 확인하고, 표현할 수 없는 표준·레거시 UV 변환을 경고하고 연결을 제외하는지 검사했다. 기본값인 레거시 배열은 허용하며, 숫자가 아닌 전용 강도 속성은 지정된 오류로 거부하고 기존 에셋 수를 유지한다. FBX 표준 연결의 강도는 외부 앱이 전용 속성을 해석한다고 주장하지 않는다.
- 편집 레이어의 UV 선택과 강도 보간, 비활성 상태에서 이력을 제한한 뒤 저장·복원, 외부 편집의 이미지 교체·참조 불일치·동시 충돌 거부를 검사했다. 유효하지 않은 이미지, 누락된 UV와 비유한 강도도 거부한다.
- 프로젝트 버전 18과 점 선택을 함께 복원했다. 독립 파서로 버전 18 헤더·CRC와 손상된 입력을 확인했다. 체크섬이 유효하지만 노멀 UV 또는 강도가 저장 스냅샷과 다른 프로젝트는 기존 엔진을 보존하며 거부한다.
- macOS의 일반 구성에서 관련 자동 회귀 122개, NSCharacter 없는 코어 전용 구성에서 92개가 통과했다. 이후 강도 속성 타입 검사를 추가하고 표준 C++23 모드로 전환하여 노멀 맵 중심 검사 5개씩을 각 구성에서 다시 통과했다. 별도 설치 스테이징의 일반 및 코어 전용 C++23 소비자도 각각 5개가 통과했고, 마지막 라이브러리 갱신 후 3개씩을 다시 통과했다. 준비된 설치 헤더와 라이브러리를 참조하는지 확인했으며, 두 라이브러리의 직접 동적 의존성에서 Qt는 확인되지 않았다.
- 최종 소스의 주소·정의되지 않은 동작 검사기 빌드에서 노멀 이미지 교환과 버전 18 프로젝트 무결성에 해당하는 7개가 통과했다.

## 남은 경계

출력 탄젠트 생성과 렌더링 품질, 다른 PBR 슬롯, 텍스처 채널·색 공간 규약 변환, Windows·Linux 실기기 검증이 남아 있다. 실제 CC5·Blender·Unreal과 SDK 사용자 앱은 사용자 지시에 따라 실행하지 않았다. 합성 포맷 검사는 실제 애플리케이션의 읽기·편집 호환성을 증명하지 않는다.
