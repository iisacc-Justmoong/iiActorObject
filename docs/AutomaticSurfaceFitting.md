# 생성·편집에 연결한 자동 표면 맞춤

## 소유권과 설정

`SurfaceFittingRule`은 본체 템플릿이 소유하는 설정이다. 대상 메시, 장애물 메시 인덱스, 맞춤 수치·점별 이동 비율, 충돌체 한도와 활성 상태를 보관한다. 원본 엔진·에셋의 소유권을 이동하거나 실행 callback을 보관하지 않는다. NSCharacter의 `CharacterEditor`는 본체 세션의 `surfaceFittings`·`setSurfaceFittings`를 호출한다.

`SurfaceFitSettings`는 `SurfaceFitOptions::mobility`의 값을 복사한다. 호출자 배열이 변경·해제되어도 저장 설정은 유지된다. `options()`는 설정 객체의 이동 비율 배열을 참조하는 일시적인 조회 값이다. 설정 객체가 유효한 동안 사용하며 임시 설정 객체에서 해당 조회를 꺼내는 호출은 금지한다.

```cpp
iiActorObject::SurfaceFitOptions options;
options.clearance = .002;
options.tolerance = 1e-5;
options.edgeStiffness = 0;
iiActorObject::SurfaceFittingRule rule;
rule.targetMesh = garmentIndex;
rule.obstacleMeshes = {bodyIndex};
rule.fitting = iiActorObject::SurfaceFitSettings(options);
editor.get().setSurfaceFittings(std::span(&rule, 1));
```

템플릿 생성자는 `Object3DTemplateDefinition::fittings`를 지정한다. 기존 편집기에서는 `setSurfaceFittings`로 설정 전체를 교체한다. 일반 스냅샷 편집기는 현재 에셋을 중립 자료로 갖는 본체 템플릿으로 전환한다. 설정 교체·해제·활성 변경과 일반 조형·생성 파라미터 변경은 같은 undo/redo 이력을 사용한다. 동일한 설정을 다시 지정하면 revision을 올리지 않는다.

## 계산 순서

1. 원본 템플릿과 파라미터에서 형상을 만들고 기존 표면 추종을 계산한다.
2. 활성 조형·스킨·모프·UV 등의 편집 계층을 순서대로 적용한다. [평가 계층](EvaluatedEditLayers.md) 앞에서는 이전 위치 편집의 추종과 자동 맞춤을 먼저 완료하여 화면에 보이는 표면 위에 새 보정을 적용한다.
3. 표면 추종과 맞춤 장애물→대상 의존성을 합친 DAG 순서로 자동 맞춤을 계산한다. 앞선 맞춤이 원본 표면을 바꾸면 후속 부착물에 그 추가 변화량을 한 번 전달한다.
4. 최종 원본 제어점으로 관절 앵커를 계산한 뒤 수동 관절 계층을 적용한다.
5. 법선·렌더 캐시와 에셋 검증을 거쳐 본체 스냅샷을 게시한다.

자동 결과는 사용자 조형 보정에 누적하여 저장하지 않는다. 체형·몸·의상·계층을 바꿀 때마다 원본과 현재 사용자 보정에서 다시 계산한다. 따라서 설정을 끄면 원본과 수동 편집이 남으며, 자동 보정만 사라진다. `Object3DTemplate::generate`도 같은 최종 맞춤 연산을 사용한다. 공개된 명시적 `fitSurface` 스냅샷 연산은 [기존 계약](SurfaceFitting.md)을 유지한다.

## 의존성과 한도

대상마다 하나의 맞춤 설정을 사용하며 설정 하나에 여러 장애물을 지정할 수 있다. 자기 참조·중복 장애물·중복 대상·표면 추종과 결합한 순환을 거부한다. 설정은 최대 64개, 장애물 메시도 설정당 최대 64개이다. 장애물은 현재 형상의 닫힌 경계를 요구한다. 열려 있는 옷을 다른 옷의 고체 장애물로 간주하지 않는다.

비평면 쿼드에는 선택적으로 반대 대각선의 파생 충돌체를 함께 사용한다. 실제 앱의 삼각화 차이에 대응하기 위한 보수적인 검사이며 작성용 원본 연결은 바꾸지 않는다. 평면 쿼드는 동일한 경계면이므로 충돌체를 중복 생성하지 않는다. 파생 충돌체는 최대 128개이다.

규칙의 `collider` 한도는 해당 규칙의 모든 파생 충돌체를 합쳐 적용한다. 원본 점·삼각형·연결 성분·전처리 방문 수를 누적하며, 각 충돌체를 만들 때 남은 전처리 한도를 전달한다. 맞춤 자체의 점 방문·BVH 노드·삼각형 검사 한도도 별도로 적용한다. 현재 생성·편집 형상에서 다시 만든 충돌체만 사용하여 이전 체형의 공간 인덱스를 재사용하지 않는다.

고정점·반복 수·이동 범위·예산 때문에 해를 얻지 못하면 생성·편집을 실패시키고 이전 스냅샷·파라미터·계층·revision을 유지한다. 자동 설정에는 `allowUnresolved` 미리보기를 허용하지 않는다. 비활성 설정도 인덱스·수치·이동 비율과 예산을 검증하며, 경계의 폐쇄성과 실제 맞춤 가능성은 실행할 때 검사한다.

오목한 틈의 국소 정체를 보완하는 `escapeConcavities` 설정도 보관한다. 탐색과 정규 투영은 같은 이동·질의 한도를 사용한다. 예산·고정점 때문에 만족할 수 없는 제약을 자동으로 완화하거나 미해결 미리보기로 바꾸지 않는다.

## 저장과 외부 앱

프로젝트 보관 이력에 계산된 표면 위의 평가 계층이 있으면 버전 10을 작성한다. 평가 계층 없이 템플릿 맞춤 설정만 있으면 버전 9를 작성한다. 규칙·장애물·자체 소유 이동 비율·수치·활성 상태를 저장하며, 충돌체의 BVH나 프로세스 주소는 저장하지 않는다. 복원은 새 본체 엔진에서 형상을 재계산하여 저장 스냅샷과 대조한다. 평가 계층과 설정이 모두 없는 프로젝트는 기존 버전 8로 작성하고 형상 정리 설정이 기본값과 다르면 버전 11을 우선 작성하며 입력은 버전 1~11을 읽는다.

FBX·GLB에는 현재 계산된 메시·스킨·모프를 출력한다. 외부 앱의 일반 파일 입력만으로 SDK 맞춤 규칙이 설치되는 것은 아니다. SDK에서 생성·상세 편집·복원한 결과의 실제 앱 삼각형 거리는 별도로 검사한다. 동적인 천·자기 충돌·애니메이션 포즈별 보정과 실제 CC5·Unreal 적용은 전체 목표의 후속 범위이다.

## 검증

`AutomaticFittingTest.cpp`는 설정 배열의 자체 소유, 직접 생성·몸/의상 조형·연쇄 추종, 결합 순환 거부, 설정 해제와 이력, 고정점, 버전 9 복원, 예산·실패 원자성을 검사한다. `AutomaticFittingHumanTest.cpp`는 기존 버전 8 인체 프로젝트의 명시적 맞춤 계층을 제거한 뒤 자동 설정만으로 성인·아동 형상과 수동 조형을 계산한다. 저장 복원 뒤의 체형 변경과 얼굴 리그 재연결도 검사한다.

Blender 검사는 자동 계산된 성인·아동의 GLB·FBX 네 입력에 기존의 독립 삼각형 거리·안팎·기준 위치·스킨·모프 검사를 적용한다. 버전 8과 9의 헤더·CRC와 잘못된 입력은 별도 Python 표준 라이브러리로 검사한다. 동결 소스·수치·산출물은 [AutomaticFittingVerification-20261027.json](AutomaticFittingVerification-20261027.json)에 기록한다.

메모리·정의되지 않은 동작 검사는 Debug 구성에 `-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -fno-optimize-sibling-calls`를 적용한다. 정적 라이브러리와 설치 소비자에 같은 구성을 사용한다. `-O1`은 [Clang AddressSanitizer 문서](https://clang.llvm.org/docs/AddressSanitizer.html)의 속도와 추적 정보 지침에 따른 선택이다. 이전 체크포인트의 최적화하지 않은 Debug 검사 시간과 이번 시간을 직접적인 성능 개선 수치로 비교하지 않는다.

성인·아동의 실제 Blender 렌더도 별도로 확인하였다. 파란 검증용 표면 조각은 체형을 따라가지만 소매와 밑단이 거칠며, 아동의 목 주위에는 국소적인 접힘과 돌출이 남아 있다. 거리 제약의 만족은 의상 제작 품질을 보장하지 않는다. 원본 의상 토폴로지·곡률 보존·자세별 보정은 후속 작업이다.

자동 규칙도 선택적인 [충돌 보정의 형상 정리](SurfaceFairing.md)를 보관한다. 이 설정만 변경해도 본체가 변경을 인식하여 원본과 사용자 계층에서 재계산한다. 이전에 맞춘 결과를 새 원본으로 굳히지 않는다.
