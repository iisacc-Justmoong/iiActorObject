# GLB 원본 탄젠트와 모프 탄젠트

GLB의 `TANGENT`와 모프 `TANGENT`는 `MeshTopology`의 불변 `sourceGlbTangents`에 원본 layout별로 보관한다. 메시와 자료의 소유자는 iiActorObject 본체이며 NSCharacter는 본체를 참조한다. 사용하지 않는 원본 정점의 탄젠트도 남긴다. 서로 다른 프리미티브의 속성 묶음은 별도 layout으로 구분하므로 같은 재질에서 탄젠트가 있는 면과 없는 면을 섞어도 재출력 때 혼동하지 않는다. 위치·스킨·위치 모프 접근자가 같다면 이 layout은 같은 본체 제어점을 참조해 함께 편집된다.

원본의 XYZ 방향과 W 부호, 각 모프의 XYZ 차이를 유지한다. 가져오며 메시 공간에 적용되는 선형 변환으로 방향과 차이를 옮기고, 기준 탄젠트의 변환된 길이로 둘을 같은 비율로 정규화한다. 이로써 모프를 임의 가중치로 적용한 뒤 방향을 정규화하면 원본 모프 방향에 변환을 적용한 결과와 같다. 반사 변환은 W의 부호를 뒤집는다. UV는 내부에서 V를 뒤집어 저장하지만 이 스냅샷의 부호는 GLB 출력 좌표의 규약으로 유지한다. 부호는 모프에 의해 바뀌지 않는다.

`sourceGlbTangents`는 기준 위치·법선·UV·토폴로지·모프와 정점별 탄젠트, 모프 탄젠트, 노멀 맵의 UV 연결을 함께 보관한다. `topologyGlbTangentsValid`는 현재 토폴로지가 그 기준과 맞는지 확인한다. 위치·법선·UV·모프 또는 연결이 달라지면 원래 탄젠트를 재사용하지 않는다. 스킨 가중치와 기본 모프 값만 바뀐 경우에는 기준이 유지된다. 원래 상태로 실행 취소하면 다시 사용할 수 있다. 노멀 맵의 UV 선택이 바뀐 재질도 원래 기저를 사용하지 않는다.

호출자가 스냅샷을 제공한 뒤에도 변경 가능한 별칭을 보유할 수 있으므로 GLB·FBX 출력과 프로젝트 저장 전에 스냅샷의 인덱스·수치·부호를 다시 검사한다. 손상된 자료는 예외로 거부하고, 형식은 정상이나 기준 형상이 달라진 자료는 이력에 저장할 수 있다. 공유 자료에 대한 동시 수정은 지원하지 않는다.

GLB 출력에서는 삼각형의 재질·원본 탄젠트 상태 분류, FBX 코너 대응과 레이어 선택, 메시별 출력 조합을 내부 처리기로 나눈다. 레이어 선택기는 변경되지 않는 메시를 빌리며 선택된 레이어와 코너 대응의 참조는 선택기와 메시의 수명 안에서만 사용한다. 이 처리기들은 최종 SDK 라이브러리에 포함된다.

기준이 유효하면 노멀 맵 유무와 관계없이 원본 탄젠트와 모프 차이를 GLB에 출력한다. 면은 현재 재질과 탄젠트 유무에 따라 분리하고 원본 layout에서 파생된 표시 정점, 스킨과 다른 모프를 함께 기록한다. 기준이 달라진 부분은 `extras.iiActorObjectAuthoredTangentStatus`에 `source_tangents_stale` 또는 `source_tangent_uv_changed`를 기록하며, 노멀 맵이 있으면 현재 UV의 [MikkTSpace 기저](MeshTangents.md)를 계산한다. 원본 상태에서 탄젠트가 없던 면도 기존 계산 경로를 따른다. 원본 기저의 정확한 내보내기가 작업 예산을 넘으면 조용히 버리지 않고 실패한다.

유효한 GLB 원본이 없는 프리미티브는 [FBX 원본 탄젠트 레이어](FbxTangents.md)가 있으면 선택된 UV와 비탄젠트 방향을 확인해 GLB 기저를 만들 수 있다. FBX의 원본 비탄젠트 전체, 추가 UV 기저, FBX shape 모프 탄젠트는 GLB의 단일 기저 속성에 완전히 보존되지 않으므로 변환 상태를 `extras`에 기록한다. 이 상태를 SDK가 다시 읽으면 제한된 경고로 전달한다.

입력의 부호는 -1 또는 +1이어야 하며, 유한하고 0이 아닌 방향이 필요하다. 부동소수점 및 필수 `KHR_mesh_quantization`의 부호 있는 정규화 정수를 지원한다. 모프 탄젠트는 기준 탄젠트가 있어야 한다. 기준 법선이 없는 프리미티브에서는 glTF 규칙에 따라 탄젠트와 그 차이를 무시하고 경고한다. 전체 입력에서 기준 탄젠트 최대 800만 개와 처리하는 모프 탄젠트 값 최대 1,600만 개를 제한한다. 재출력은 전체 원본 탄젠트 작업량을 2억 5,600만, 프리미티브의 출력 모프 델타를 1,600만 개로 제한한다.

프로젝트 버전 24는 스냅샷과 편집 이력 간 공유를 저장한다. 버전 1~23에는 이 필드가 없으며 다른 자료만 있는 프로젝트는 필요한 기존 버전으로 작성한다. 공개 자료 구조가 변경되어 C++ 소비자는 다시 빌드해야 한다. 유효한 기준 탄젠트는 원래 노멀 맵 UV 연결이 유지된 면에 한해 [FBX 레이어](FbxTangents.md)에도 옮긴다. FBX 원본 탄젠트 레이어는 별도 경로이며 GLB의 모프 탄젠트 차이가 FBX shape에 옮겨지는 것은 아니다. 실제 CC5·Blender·Unreal의 실행이나 렌더 결과는 이 계약으로 확인하지 않는다.
