# 외부 삼각형 메시의 편집 병합

`Object3DExternalIdentity`는 원본 폴리곤에 대한 기존 대응 외에, 원본의 표시 삼각형과 외부 삼각형을 직접 연결하는 방식을 지원한다. 이 방식은 사각형 등의 작성용 폴리곤을 삼각형으로 내보낸 후의 위치·스킨·UV·모프·기준 법선·재질·관절 편집을 본체의 원본 폴리곤과 비파괴 편집 이력에 반영하기 위한 것이다. 공용 계산과 자료는 iiActorObject 본체가 소유하며 `NSCharacter::CharacterEditor`는 같은 본체 병합을 호출한다.

## 대응 계약

호스트가 기준 및 편집 스냅샷 각각의 `ExternalMeshIdentity`에 `topology = ExternalMeshTopology::RenderTriangles`를 지정한다. `points`는 스냅샷 제어점마다 원본 제어점 ID를 제공한다. `polygons`에는 각 외부 삼각형에 대응하는 원본 표시 삼각형 번호를 넣는다. 이 번호는 원본 `MeshTopologyLayout::triangles()`에서 세 인덱스씩 묶은 순서이며 렌더 토폴로지만 있는 메시도 같은 규칙을 사용한다. `corners`는 외부 삼각형 코너마다 원본의 layout ID를 순서대로 제공한다.

모든 원본 제어점·본·메시·머티리얼을 기존 [외부 편집 계약](ExternalEdits.md)에 따라 대응해야 한다. 원본의 모든 표시 삼각형은 정확히 한 번씩 있어야 하며 외부 삼각형의 점과 원본 코너 연결이 일치해야 한다. 숨긴 폴리곤은 표시 삼각형에 포함되지 않으며 원본에 그대로 남는다. 스냅샷의 삼각형과 정점 순서는 달라도 되지만 각 스냅샷에 그 순서에 맞는 ID를 제공해야 한다. 기준과 편집 스냅샷의 대응 방식은 같아야 하고, 기준에서 편집으로 삼각형의 코너 순서가 뒤집히면 거부한다.

중복·누락·범위 밖 삼각형, 잘못된 코너나 제어점, 다른 문서 토큰, 원본 토폴로지 변경 및 기존 편집 계약의 충돌은 결과와 이력을 변경하지 않고 거부한다. 기준 파일은 원본에 해당하는 위치·스킨·UV·관절·모프를 유지해야 하며, 수치 오차 허용치는 기존 `Object3DExternalOptions`를 따른다. 반영된 차이는 기존 레이어의 교체·undo·redo·템플릿 파라미터 변경과 함께 사용할 수 있다.

`ExternalMeshIdentity`의 공개 C++ 레이아웃이 바뀌었으므로 소비자는 새 헤더와 라이브러리로 다시 빌드해야 한다. 프로젝트 저장 형식은 바뀌지 않는다. 삼각형 대응 자료는 외부 스냅샷의 호출용 식별 자료이며 엔진이 소유하는 메시나 리그의 별도 복사본이 아니다.

## GLB 자동 대응과 한계

[GLB 외부 편집 자동 대응](GlbExternalEdits.md)은 선택적 작업 토큰과 원본 메시·본·머티리얼 번호, 복원된 원본 점 번호에서 이 삼각형·코너 대응을 생성한다. 각 삼각형의 세 점 번호가 유일해야 하며, 중복되거나 사라진 정보는 추측하지 않고 거부한다. 메타데이터가 없는 다른 교환 형식은 호스트가 계속 명시적으로 대응을 제공할 수 있다.

외부 도구가 사용자 정의 정보를 보존한다는 보장은 없다. 본·모프 이름 변경, 미사용 머티리얼, UV 이름과 애니메이션 등 GLB 경로의 현재 제한은 해당 문서에서 확인한다. 실제 CC5·Blender·Unreal 실행이나 제작용 MetaHuman 품질은 검증하지 않았다.

## 검증 기록

2026-10-28 macOS arm64에서 일반 구성과 NSCharacter를 끈 코어 단독 구성의 외부 편집·GLB·FBX·프로젝트 회귀 검사 각각 33개가 통과했다. 동일한 검사가 두 구성에 포함된다. SDK에서 생성한 GLB를 입력으로 삼아 호스트가 직접 원본 삼각형·코너 대응을 구성한 시료에서 위치·스킨·UV·모프·재질·관절·기준 법선의 편집, 삼각형 순서 변경, 숨김 면과 원본 사각형 유지, 이력의 undo·redo와 NSCharacter 호출을 확인했다. 두 재질과 UV 이음새 시료에서는 같은 점의 위치는 공유하고 UV는 각 원본 코너에 남는지 확인했다. 중복·누락·잘못된 ID와 서로 다른 대응 방식은 실패 후 revision을 유지했다.

CC0 MakeHuman 시료 하나는 원본 점 19,158개, 본 163개, 표시 삼각형 코너 80,268개를 사용했다. SDK가 생성한 GLB의 삼각형을 원본 순서와 점 번호로 확인한 다음 테스트에서 직접 대응을 만들고 한 점의 스킨 가중치 변경과 undo·redo, 원본 폴리곤 유지가 통과했다. 이것은 외부 앱이 대응을 보존한다는 증거가 아니다.

AddressSanitizer·UndefinedBehaviorSanitizer 구성의 관련 검사 5개가 통과했다. 정의되지 않은 동작 발견 시 중단하도록 했고 누수 검출은 끈 상태였다. `build/`의 별도 설치본을 사용하는 코어 소비자와 일반 소비자 검사도 통과했으며, 검사한 두 macOS 라이브러리의 동적 의존성에 Qt는 없다. 설치 헤더와 라이브러리는 해당 빌드 결과와 일치한다. 사용자 홈 설치본은 교체하지 않았다. CC5·Blender·Unreal, Windows·Linux 및 제작용 MetaHuman 시각 품질은 검사하지 않았다.
