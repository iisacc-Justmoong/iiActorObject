# 인체 부속 교체와 접지 검증 기록

이 문서는 당시 교체 기능을 검사한 이력이다. 이후 부속 제거와 인덱스 재연결은 [제거 검증 기록](HumanAccessoryRemovalVerification-20261029.md)에서 다룬다.

## 범위와 입력

[인체 부속 선택과 편집 계약](HumanAccessories.md)의 같은 슬롯·같은 분류 교체를 검사했다. MakeHuman의 CC0 인체, `hair/bob01`, `hair/short01`, `clothes/female_casualsuit01`, `clothes/male_casualsuit01`, 눈썹·속눈썹과 피부 PNG 자료를 사용했다. 부속 원본의 획득 범위와 무결성 기록은 [생성 검증](HumanAccessoriesVerification-20261029.md)에 있다. 인체와 이력은 iiActorObject 본체가 소유하며 NSCharacter는 본체의 편집기를 참조한다.

몸의 머리 폭 파라미터, 원본 점 조형, 재질 속성, `young_african_male` 피부 이미지와 이름 있는 몸 점 선택을 적용한 후 머리카락과 의상을 순차 교체했다. 몸의 스킨 가중치를 직접 바꾼 세 원본 대응 점에서 새 머리카락으로 변경된 본 영향을 전사하는 것도 검사했다. 원본 몸의 위치·피부 이미지·재질 속성·선택을 유지하고 교체 전후 undo/redo와 프로젝트 재복원 후 파라미터 변경이 동작했다. 교체 대상에 직접 점 조형이나 선택·재질 편집이 걸린 경우, 공유 재질, 다른 엔진과 중복 슬롯을 거부하는 검사도 포함한다. 머리카락과 의상을 한 번에 바꾸면 한 번의 undo로 이전 조합을 되돌린다. 의상 자체에 조형과 점 선택이 있는 상태의 몸 가림 토글은 해당 의상 편집을 유지한다.

## 접지와 프로젝트 호환

접지 메시의 표시 원본 점이 바뀌면 이전 표시 점 집합을 템플릿에 고정한다. 독립적인 축소 예제에서 점을 숨길 때와 드러낼 때 모두, 교체 전의 지지점이 추후 타깃 값에 따라 달라지는 경우까지 몸의 위치를 원래 템플릿과 비교했다. 가림 상태 교체의 undo/redo와 프로젝트 버전 32로 저장·복원한 뒤 추가 형상 변경도 검사했다. 중복·범위 밖의 명시 지지점은 거부하며, 접지 중 나머지 메시와 루트 본의 이동 및 스킨 동작도 기존 접지 테스트로 검사했다. 버전 1~8의 기존 프로젝트 fixture와 버전 8의 접지 프로젝트를 계속 읽었다. 버전 32는 명시 지지점이 필요할 때만 선택한다.

매크로 자료의 820개 타깃과 발 접지 옵션을 사용한 인체에서 나이·키·질량을 정한 후 머리카락과 의상을 교체하고 몸 원본 점 위치를 비교했다. 이어서 나이와 키를 변경했을 때의 몸 점은 교체 전 템플릿에서 같은 값을 생성한 결과와 일치했다. 이 실측은 해당 예제의 자료와 점에 한정한다. 기존 지지점을 계속 쓰므로 새로 보이는 점이 바닥 아래에 있을 수 있으며, 새 표시 표면 기준의 재접지가 필요하면 호스트가 별도로 선택해야 한다.

## 파일과 크기

별도 Python 판독기로 교체 전후의 GLB 및 FBX를 조사했다. 교체 전 여성 의상의 원본 가림 점과 몸 OBJ에서 숨긴 폴리곤 2,688개와 표시 삼각형 21,380개를 계산했다. 남성 의상 교체 후에는 각각 3,364개와 20,028개였다. 새 이미지의 원본 바이트, 머리카락의 알파·양면 재질, 의상 노멀 이미지, 각 메시의 스킨·본 연결 및 정규화된 점별 가중치도 검사했다. 외부 앱의 가져오기나 화면 표시 결과를 확인한 것은 아니다.

하나의 인체 편집 예제에서 이력 제한을 4로 설정한 프로젝트는 222,944,660바이트였다. 제한을 32로 하여 이전 편집을 더 유지한 프로젝트는 288,930,181바이트였고 기본 256 MiB 파일 예산을 넘었다. 기본 예산 저장 실패 후 편집 revision과 에셋·엔진 자원 수가 바뀌지 않는 것을 확인했다. 해당 사례는 `maximumBytes=768 MiB`, `maximumDecodedBytes=1536 MiB`, `maximumElements=64,000,000`을 명시하여 저장·복원했다. 제한값 32는 이력 용량 설정이며 32번의 편집이 저장되었다는 뜻은 아니다.

별도의 600점 합성 몸 조형 검사에서는 한 점 대신 600점을 편집한 데 따른 프로젝트 크기 차이가 교체 전과 여섯 번 교체 후 모두 19,168바이트였다. 바뀌지 않은 조형 보정 자료가 교체 이력마다 복제되지 않는지 살펴본 특정 예제이며 전체 프로젝트 크기나 메모리의 일반 성능 보장은 아니다.

## 빌드와 자동 검사

- macOS arm64 C++23 Release: 교체·접지·인체 편집과 교체 후 독립 GLB/FBX 검사 14/14, 매크로 인체 교체 1/1 통과. `build/glb-import-ninja/surface-swap-grounding-final.xml`, `human-accessory-grounded.xml`.
- NSCharacter 제외 본체 전용 Release: 접지, 표면 교체, 템플릿 적응, 프로젝트, 편집 계층과 점진 모프 회귀 80/80 통과. `build/core-tangent-ninja/surface-swap-grounding-regression.xml`.
- NSCharacter 포함 Debug ASan·UBSan: 접지·표면 교체·인체 편집과 독립 형식 검사 13/13 통과. 누수 검출은 비활성화했다. `build/glb-import-full-asan/surface-swap-grounding-asan.xml`.
- `build/` 안에 별도 설치한 패키지의 본체 전용 공개 API 소비자 1/1, NSCharacter 포함 소비자 2/2가 통과했다. 본체 소비자는 명시 접지점 API도 호출했다. 사용자 설치본은 변경하지 않았다. 각 소비자 빌드의 `human-surface-grounding.xml`.
- Emscripten C++23으로 변경된 템플릿·교체·프로젝트·NSCharacter 소스의 구문 검사를 통과했다. macOS 빌드의 생성된 기능 설정을 사용했으며 전체 SDK의 WebAssembly 링크·실행 결과는 아니다.
- macOS 라이브러리의 직접 동적 링크 목록은 C++ 표준 라이브러리와 시스템 라이브러리만 포함했다. Qt 직접 링크는 확인되지 않았다.

## 남은 기능과 검증

슬롯 추가·삭제, 편집된 기존 부속 조형의 새 형상 전사, 공유 재질·이미지와 다중 재질 부속 교체는 구현하지 않았다. 대상이 다른 연결·맞춤의 기반이거나 편집·선택되어 있으면 거부한다. 이전 에셋 스냅샷에 연결된 리그는 필요할 때 다시 연결해야 한다. 의상 간 가림 순서, 천·머리카락 물리, 자세별 충돌 제거, 이미지와 이력 중복 저장 최적화 및 제작용 셰이더도 남아 있다.

사용자 지시에 따라 CC5·Blender·Unreal과 사용자용 앱은 실행하지 않았다. 따라서 이 기록은 실제 호스트 간 가져오기·렌더링 호환성이나 MetaHuman 수준의 완성도를 증명하지 않는다. 전체 캐릭터 생성·상세 편집 목표는 계속 진행 중이다.
