# 모프 채널 리그와 절차적 혀 검증 — 2026-10-28

## 변경 범위

`createObject3DMorphChannelRig`는 한 코어 에셋에 작성된 모프 이름을 모아 여러 메시의 같은 이름에 적용하는 정규화된 리그를 만든다. 기존 템플릿 모프 리그와 프로젝트 저장 형식을 사용하며 실제 템플릿·샘플 출처를 임의로 만들어 내지 않는다. 관절 자세와 원본 에셋을 변경하지 않는다.

얼굴 모프를 사용하는 절차적 인체에는 턱 본에 바인딩된 단순한 혀 메시와 `tongueOut`, `jawOpen`, `jawForward`, `jawLeft`, `jawRight` 모프를 추가했다. 혀와 몸체의 같은 이름 제어는 리그에서 함께 평가한다. 해부학적으로 완성된 구강이나 몸체·치아와의 충돌 처리를 뜻하지 않는다.

## 검사 결과

- macOS arm64 Release의 코어 전용과 NSCharacter 포함 구성을 C++23으로 빌드했고 각각 리그 테스트 4개가 통과했다. 테스트는 여러 메시의 채널 순서와 공유, 기본값, 관절 보존, 범위와 누락, 재연결 실패, 프로젝트 저장·복원을 다룬다.
- NSCharacter 포함 구성의 기존 생성·편집·스킨·FBX·GLB 회귀 테스트 17개가 통과했다. 절차적 구강의 네이티브 fixture와 독립 형식 검사 2개도 통과했다.
- 구강 fixture는 다섯 모프의 이동 방향, 모프 끝점 법선, 턱 스킨, 기존 자세 보존, 얼굴과 혀의 공동 제어, 체형 변경과 지정된 매개변수 범위의 양 끝을 확인했다. 리그를 프로젝트에 저장·복원하여 같은 제어를 다시 평가했다.
- 독립 Python 판독기는 GLB와 FBX에서 혀의 정점과 `tongueOut` 델타, 턱 본과 스킨 가중치를 읽어 원본 수치와 비교했다. 실제 앱의 파일 가져오기나 표정 슬라이더 연결을 확인한 결과는 아니다.
- 프로젝트 `build/` 아래에 별도로 설치한 코어 전용과 NSCharacter 포함 소비자의 새 리그 API 빌드와 테스트가 각 1개씩 통과했다. 사용자 전역 설치본은 변경하지 않았다.
- 두 라이브러리의 직접 동적 의존성은 C++ 런타임과 macOS 시스템 라이브러리이며 Qt는 표시되지 않았다. 다른 플랫폼이나 전체 의존성 라이선스 감사의 근거는 아니다.
- 새 API 테스트는 구현 전 미선언 오류를 확인한 뒤 구현 후 통과했다. 첫 NSCharacter 빌드는 설정 재생성 이전 타깃 목록 때문에 새 테스트를 찾지 못했으며, 생성된 타깃을 확인하고 재실행하여 성공했다. 기존 눈 재질의 일부 필드 명시 초기화 경고는 남아 있다.

사용자의 지시에 따라 CC5·Blender·Unreal 및 사용자용 애플리케이션은 실행하지 않았다. 피부 표면과 혀의 관통, 정밀한 치아·구강 구성, 제작용 외형과 실제 대상 호스트에서의 제어 연결은 이 결과에 포함되지 않는다.
