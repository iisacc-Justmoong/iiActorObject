# 외부 앱의 상세 편집을 본체에 반영

## 자료와 소유권

원본 캐릭터는 본체 엔진의 편집 프로젝트로 유지한다. 외부 앱에는 FBX와 원본 ID를 함께 내보내고, 앱이 수정 없이 재출력한 기준 파일과 실제 편집 파일을 비교한다. `Object3DExternalSnapshot`은 본체 자산과 대응 정보의 참조이다. NSCharacter는 본체 편집 세션을 호출하며 별도 메시·리그 저장소를 만들지 않는다.

`FbxExportOptions::externalDocument`를 지정하면 문서 토큰, 원본 본·메시·제어점·폴리곤·코너 layout·모프·머티리얼 대응을 FBX 사용자 속성에 기록한다. 기본 내보내기에는 이 추가 속성을 넣지 않는다. `Object3DImport::externalIdentity`가 읽은 대응을 반환한다. 문서 토큰은 128바이트 이하의 비어 있지 않은 값이며, 원본 프로젝트와 함께 보관한다.

식별 값만 필요한 소비자는 `<iiActorObject/Object3DExternalIdentity.h>`를 직접 포함할 수 있다. 기존 `Object3DExternalEdits.h`도 같은 선언을 계속 제공한다. 식별 자료는 에셋이나 엔진을 소유하지 않는다.

같은 이름의 원본 모프 레코드가 여러 개라면 외부 편집용 FBX는 이를 하나의 논리 채널로 투영한다. 원본 레코드 분할은 투영 파일에 없으며 기준 에셋과 프로젝트에 보관된다. 차이 병합, 법선, 이름 변경과 삭제의 계약은 [논리 모프 채널](LogicalMorphChannels.md)에 정리한다.

Blender 보조 어댑터는 제어점·면·코너 ID를 메시의 INT 속성에 보관하고 내보낼 때 현재 순서로 사용자 속성을 갱신한다. 본과 머티리얼의 ID도 사용자 속성으로 유지한다. 앱이 배열을 정렬하거나 표시 이름을 바꾸어도 원본 ID를 다시 매기지 않는다.

FBX shininess와 PBR 거칠기의 변환 규칙은 앱마다 다르다. Blender `import_fbx`는 사용자 속성에 보관한 원본 거칠기·금속성을 새로 가져온 재질에 한 번 복원한 후 기준 파일을 만든다. 이미 열린 장면에 `ExternalSession`을 연결할 때는 현재 재질 값을 덮어쓰지 않는다. 내보내기는 현재 Principled 값과 사용자 속성을 함께 갱신한다.

## 비교와 반영

`applyObject3DExternalEdits(current, source, baseline, edited, options)`는 원본 ID의 자료에 외부 편집 차이를 반영하는 본체 함수이다. `source`는 외부 작업 시작 시의 정본이다. 문서 토큰·전체 대응·원본 제어점과 관절 위치·스킨을 검사하여 다른 자료를 잘못 연결하는 것을 거부한다. 기준 파일과 편집 파일의 본 배열 순서·메시 순서는 같을 필요가 없다.

원본 작성용 폴리곤을 외부에서 삼각형으로 표현한 경우에는 [표시 삼각형 대응](ExternalTriangleEdits.md)을 명시할 수 있다. 모든 표시 삼각형과 원본 코너 ID의 대응이 필요하며, GLB 가져오기가 이 코너 대응을 자동 제공하는 것은 아니다.

- 위치와 UV·모프 위치 델타, 머티리얼 수치는 편집 파일에서 기준 파일을 뺀 차이를 현재 정본에 더한다. 생성 파라미터를 바꾼 뒤에도 외부의 국소 보정을 유지한다.
- 가중치는 원본 본 ID로 변환한 목표 행을 적용한다. 현재 행도 원본 이후에 바뀌었다면 기본적으로 충돌을 거부한다. `overwriteConflicts`는 호출자가 명시하는 덮어쓰기이다.
- 관절은 앱의 기준 자세와 편집 자세 사이의 선형 변환 차이와 위치 차이를 현재 정본의 기준 행렬에 적용한다. 앱의 고정 좌표축 표현을 정본의 회전으로 덮어쓰지 않는다. 새 부모와 표시 이름은 원본 본 ID를 유지하여 적용한다.
- 모프의 표시 이름과 위치 델타·명시적 layout별 법선 계수를 반영하고 원본 target ID를 보존한다. 새 모프는 원본 target ID가 없는 보정으로 추가하며, 삭제된 원본 모프는 ID를 유지한 빈 타깃으로 만든다. 다른 편집의 법선 계수는 유지한다.
- 작성용 연결·UV·숨김 면·사용하지 않는 제어점은 보존한다. 기준 법선은 위치 변화에 따른 기하 법선과 외부의 방향 편집을 구분해 반영한다. 공유 법선 ID를 서로 다른 방향으로 분리하는 편집은 거부한다. [기준 법선 편집 계약](BaseNormalEditing.md)을 따른다.

기본 위치·속성·행렬 허용값은 `1e-6`, 원본 대응 검사의 위치 허용값은 `2e-5`이다. 각 값은 호출자가 지정하며, 유한한 0~`1e-2` 범위여야 한다. 순환·원본 ID의 중복·누락·범위 오류·다른 문서·유효하지 않은 스킨·표현할 수 없는 로컬 전단·충돌은 원본을 변경하지 않고 실패한다.

외부 FBX의 스킨 기준 행렬에는 float 재출력 오차가 있을 수 있다. 가져오기 단계는 별도 `FbxImportOptions::maximumJointMatrixError`를 사용하며 기본값 `1e-7`을 넘기려면 호출자가 값을 지정해야 한다. 편집 병합의 로컬 TRS 복원은 `matrixTolerance`와 내부 산술 오차 하한 `1e-9` 중 큰 값을 사용한다. 허용 범위 안에서 TRS로 복원한 최대 상대 행렬 오차는 `Object3DExternalReport::maximumJointMatrixError`로 반환한다. 이 허용값을 넘는 전단은 실패한다. 일반 본 편집 함수의 엄격한 전단 판정은 바꾸지 않는다.

## Blender 호출 예

원본의 균일 bind scale은 [스케일 교환 계약](SkeletonScale.md)에 따라 단위 골격으로 내보낸다. 원본 프로젝트는 원래 스케일·본 좌표계를 유지하며 병합은 기준/편집 행렬의 차이만 원본에 적용한다. 별도 원본 프로젝트를 단위 골격으로 덮어쓸 필요가 없다.

Blender의 Python Console이나 스크립트에서 설치된 `share/iiActorObject/integration/BlenderExternalEdits.py`를 불러와 다음 순서로 사용한다.

```python
session = ExternalSession.import_fbx("Tagged.fbx")
session.export_fbx("Baseline.fbx")
# 이 장면에서 정점·가중치·UV·본·shape key 등을 편집한다.
session.export_fbx("Edited.fbx")
```

장면을 다시 열었으면 `ExternalSession(document=기존_문서_토큰)`으로 기존 INT 속성과 원본 ID를 이어서 사용한다. Blender 버전이 KeyBlock 사용자 속성을 지원하지 않는 경우 현재 세션은 RNA 식별자로 모프 이름 변경을 추적한다. 세션을 닫기 전에 `export_fbx`로 이름 대응을 갱신하고 `.blend`를 저장해야 그 대응이 다음 세션에 남는다. 신규 정점의 자동 ID 추정, 누락된 머티리얼의 자동 대응은 수행하지 않는다.

## 편집 이력과 반복 불러오기

`Object3DEditor::applyExternalEdits`는 한 번의 반영을 하나의 보정 레이어 또는 snapshot 이력으로 만든다. `NSCharacter::CharacterEditor`는 같은 본체 함수를 전달한다. 원본 템플릿과 파라미터·이전 레이어를 유지하고 undo·redo 및 `.ii3dproject` 저장·복원을 사용한다.

템플릿 편집기에서 반환한 `report.layer`를 다음 호출의 `options.replaceLayer`로 지정하면 같은 외부 작업의 최신 파일로 해당 레이어를 교체한다. 처음 내보낸 기준 파일에 대한 전체 차이를 다시 더하지 않는다. 해당 레이어보다 앞선 상태에서 새 보정을 계산하고 뒤의 레이어를 다시 적용한다. 레이어 ID·순서·강도·마스크를 유지한다. 파일이 모든 편집을 되돌리면 빈 보정 레이어로 같은 ID를 유지한다. 교체 호출은 이력으로 기록하며, 호스트는 같은 파일을 반복 읽지 않도록 파일 변경을 관리한다.

의상 등의 표면 연결은 현재 전체 위치를 기준 좌표로 역산한 뒤 외부의 절대 결과에 맞는 보정만 보관한다. 따라서 외부에서 이미 조정한 의상에 몸의 추종 변위를 다시 더하지 않는다. `unapplyMeshSurfaceBindings`는 DAG의 최종 원본 표면을 참조하여 이 역산을 수행한다. 활성 자동 맞춤이 있으면 [계산된 표면 위의 평가 계층](EvaluatedEditLayers.md)을 만들고, 해당 계층 앞의 계산된 형상을 역산 기준으로 사용한다. 맞춤 전 원본에 가시 형상의 이동량을 적용하여 간격을 잃지 않는다.

## 현재 경계

원본 전체 제어점·본·메시·머티리얼 대응을 요구한다. 정본의 개수와 연결이 바뀐 경우 새 외부 작업을 시작해야 한다. 정점 추가·삭제, 면 연결·와인딩 변경, 새 UV seam과 face별 머티리얼 재배치는 별도 작성용 토폴로지 편집 경로이다. 공유 UV의 편집 값이 코너마다 달라져 새 인덱스가 필요하면 거부한다. 비균일 전단을 조용히 SRT로 근사하지 않는다.

실제 앱의 재출력과 C++ 재입력은 수치·원본 ID·재편집 가능성의 검증이다. 제작용 MetaHuman 외형, 실제 CC5·Unreal, 전체 얼굴 동작 표와 모든 토폴로지 편집의 완료를 뜻하지 않는다.

## 검증 스냅샷

2026-10-26 macOS arm64에서 다음 검증 행렬을 통과하였다. 소스와 공개 설치 헤더, 라이브러리·원본 자료·앱 산출물의 해시는 [검증 보고서](ExternalEditsVerification-20261026.json)에 기록한다. 이전 보고서들은 각 단계의 역사적 스냅샷이다.

| 구성 | 라이브러리 테스트 | 별도 설치본 소비자 |
| --- | --- | --- |
| Release 공유 라이브러리, NSCharacter·DNA·실제 Blender | 200/200 | 3/3 |
| Release 공유 라이브러리, NSCharacter 제외 | 152/152 | 2/2 |
| Debug 정적 라이브러리, ASan·UBSan | 177/177 | 3/3 |
| Release 공유 라이브러리, NSCharacter·DNA 제외 | 130/130 | 1/1 |

위 행렬은 668회의 성공한 테스트 실행이다. 코어 전용 심벌에는 NSCharacter가 없고 직접 동적 의존성·미해결 심벌에는 Qt가 없다. 본체 엔진 소멸 후 NSCharacter 참조의 만료, 자료 주소 공유, 원본 ID 보존과 실패 시 원본 유지도 포함한다.

실제 Blender 4.5.9 LTS에서는 19,158개 원본 제어점·163개 본·2개 메시의 인체를 편집하였다. 정점 순서를 바꾸고 한 점을 3mm 이동하였으며 가중치 한 행·14,517개 UV·거칠기를 수정하였다. 본을 10mm 이동하고 다른 본의 부모와 표시 이름을 바꾸었다. 본체의 파라미터를 바꾼 뒤 이 편집을 한 레이어로 반영하고 같은 레이어를 반복 교체하였다. 설정한 이동량 대비 병합 오차는 점 `2.61e-11m`, 본 `7.66e-10m`이며, 의상 오차는 `1.50e-19m` 미만이다. 최종 GLB의 거칠기는 `0.4200000107`, 편집하지 않은 의상은 `0.8`이다.

별도 작은 모프 fixture에서는 정점 재정렬 후 기존 모프를 수정·이름 변경하고 새 모프를 추가하여 원본 target ID `42`의 유지와 undo·redo·프로젝트 저장을 확인하였다. 이 fixture를 제작용 얼굴 리그의 품질 증거로 사용하지 않는다.

[여러 UV 세트](MultipleUvSets.md)의 같은 이름·정본 ID에 대응하는 좌표 차이와 머티리얼의 UV 세트 선택도 병합한다. 기준 UV가 원본과 다르거나 세트의 이름·개수·공유 인덱스 연결이 바뀌면 거부한다.
