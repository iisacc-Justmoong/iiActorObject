# 인체 부속 혼합 변경 검증 기록

## 범위와 소유권

인체 부속 편집에 동일 작업의 제거·추가를 함께 적용하는 경로를 추가했다. 예를 들어 기존 머리카락과 의상을 없애면서 다른 머리카락을 넣을 수 있다. 실제 메시·표면 연결·스킨·리소스·이력은 iiActorObject 본체가 소유하며, NSCharacter는 카탈로그의 이름과 분류를 해석해 본체 편집기에 전달한다. `Object3DEditor::changeTemplateSurfaces`는 제거와 추가 및 선택적인 표시 면 갱신을 한 이력 단계로 처리한다.

남은 표면의 순서, 원본 점, 조형 계층·점 마스크와 명명 선택은 보존한다. 새 추종 표면은 현재 편집된 원본 스킨에서 가중치를 얻고 현재 몸의 생성 및 편집에 따라 변형된다. 제거되는 표면의 편집·마스크·선택은 기본적으로 보호한다. 명시적으로 버리도록 선택한 경우 이전 이력이 남아 있는 동안 undo로 복구할 수 있다. 제거되는 메시가 타깃·관절 앵커·접지·남은 추종 표면이나 자동 맞춤에 필요한 경우 거부한다. 실패 시 현재 편집기와 등록된 에셋·템플릿을 바꾸지 않는다.

## 검사한 동작

합성 메시 테스트에서 몸과 남는 부속을 조형한 뒤 기존 부속 하나를 제거하고 두 개를 추가했다. 남은 부속의 선택 및 계층 마스크가 새 메시 번호로 이동하고 위치는 유지되는지 확인했다. 새 표면에는 편집된 몸의 본 가중치가 복사됐다. 요소 수가 증가하는 경우와 같아지는 경우 모두 프로젝트 버전 35로 저장하고 선택 상태 및 undo/redo를 복원했다. CRC를 다시 계산한 파일에서 메시 대응을 중복하거나 버전을 낮추면 복원이 거부됐다. 제거 대상의 편집 보호·명시적 폐기·undo, 중복 슬롯과 다른 표면이 제거 대상을 참조하는 경우의 거부도 검사했다.

같은 분류의 A·B 부속을 B·C로 바꾸는 합성 카탈로그 사례에서 B가 슬롯을 옮길 때 B의 조형·점 선택을 보존하는지 별도로 검사했다. 처음에는 같은 분류 교체로 잘못 분류해 B의 선택 때문에 실패했으며, 유지되는 이름이 이동하는 경우 혼합 변경 경로를 사용하도록 수정했다. 이 카탈로그는 분류 검사 전용 테스트 자료이다.

CC0 MakeHuman 자료에서는 머리카락·의상·눈썹·속눈썹 구성에서 머리카락과 의상을 제거하고 다른 머리카락을 추가했다. 몸과 유지되는 눈썹의 조형, 눈썹 점 마스크·선택, 변경 한 단계의 undo/redo 및 프로젝트 저장·복원을 확인했다. 독립 GLB·FBX 판독기는 남은 네 메시의 스킨과 정규화된 가중치, 재질 및 이미지 바이트, 옷이 제거된 몸의 표시 삼각형 26,756개를 확인했다. 사용하지 않게 된 기존 머리카락과 의상의 리소스는 내보내기에도 남아 있다.

프로젝트 버전 35는 선택 대응이 실제로 바뀐 혼합 편집 이력에만 필요하다. 복원 시 남은 메시의 이름·원본 점 연결·순서와 선택 행을 검사한다. 순수 추가·제거의 기존 버전 34·33과 관련 이력이 없는 과거 버전 선택은 유지한다.

## 빌드와 검사의 경계

- macOS arm64 C++23 Release: 본체 표면 편집 9/9가 통과했다. 최종 분류 수정 후 같은 분류 부속의 슬롯 이동, 기존 다중 교체, 인체 혼합 편집 및 혼합 변경 GLB·FBX 독립 판독 4/4가 통과했다. 그 전 추가·제거·표시·접지·실패 보호 등 인체 회귀 검사 6/6도 통과했다.
- NSCharacter를 제외한 본체 Release 구성에서도 표면 편집 9/9가 통과했다.
- 본체의 기존 명명 선택·선택 전사·프로젝트 및 이전 형식 회귀 검사는 관련 테스트 실행 파일을 현재 헤더로 다시 빌드한 후 49/49가 통과했다. 재빌드 전에는 명명 선택 fixture 하나가 `Invalid object grounding plane`으로 한 차례 실패하여 그에 의존한 검사가 실행되지 않았다. 당시 실행 파일은 현재 템플릿 헤더보다 오래된 상태였고, 재실행과 재빌드 후에는 통과했다. 실패의 근본 원인은 별도로 확정하지 않았다.
- Debug ASan·UBSan: 본체 추가·제거·의존 그래프·혼합 편집 4/4와 인체 혼합 편집·같은 분류 슬롯 이동 2/2가 통과했다. 누수 검출은 비활성화했다.
- `build/` 아래 별도 설치한 본체 전용 소비자 1/1과 NSCharacter 포함 소비자 2/2가 통과했다. 공개 혼합 변경 API와 버전 35 이력 복원, 인체 부속 교체를 검사했다. 사용자 설치본은 변경하지 않았다.
- Emscripten C++23 구문 검사는 macOS에서 생성된 기능 설정을 사용했다. WebAssembly 전체 빌드·링크·실행을 입증하지 않는다.
- macOS 라이브러리의 직접 동적 링크는 C++ 표준 라이브러리와 시스템 라이브러리이다. 직접 Qt 링크는 나타나지 않았다.

## 남은 작업

이 검증 시점에는 유지하는 부속 자체의 재정렬, 교체되는 형상으로 기존 부속의 조형을 전사하는 기능, 미사용 재질·이미지 정리, 편집된 에셋의 기존 리그 자동 재연결을 구현하지 않았다. 이후 [편집 리그 참조](EditorRigFollow.md)가 리그 조회·평가 시의 재연결을 제공한다. 추가 표면이 자체 생성 타깃·관절 앵커·접지 기준이거나 작성된 탄젠트가 재질 번호 변경으로 무효화되는 경우는 거부한다. 의상 간 가림, 천·머리카락 물리, 자기 충돌과 자세별 자동 충돌 보정도 남아 있다.

사용자의 지시에 따라 CC5·Blender·Unreal 또는 사용자용 앱은 실행하지 않았다. 독립 형식과 네이티브 검사만으로 외부 앱의 실제 가져오기, 시각 품질 또는 전체 MetaHuman 수준의 캐릭터 제작 목표가 완료됐다고 판단할 수 없다.
