# GLB 문서 판독 검증 — 2026-10-28

## 검증 범위

공용 코어의 `GlbDocument`는 메모리 입력의 GLB 컨테이너, 단일 임베디드 버퍼, 버퍼 뷰 및 접근자를 해석한다. 이 단계는 편집 가능한 메시·리그·애니메이션 가져오기가 아니다. 상세 계약과 미구현 경계는 [GLB 문서 판독](GlbDocument.md)에 기록한다.

## 직접 네이티브 검사

- 미구현 단계에서 공개 헤더가 없어 테스트 컴파일이 실패하는 것을 확인한 뒤 C++23 판독기를 구현했다.
- 수동으로 구성한 바이트에서 인터리브 U8 정규화, 음수 I8·I16 정규화의 극값, U32 최대값, 희소 원소, 기존 데이터에 희소 덮어쓰기, U16 MAT3의 열 패딩, 원본 입력 해제 후의 데이터와 버퍼 뷰를 검사했다.
- 손상된 컨테이너·길이·인덱스·stride·정렬·외부 URI·자료형, 크기와 항목 예산 및 부동소수점 무한대의 거부를 확인했다. 결정적 시드로 정상 fixture의 바이트를 변형한 2,500건도 제한된 예산에서 판독하고 오류를 처리했다.
- 판독기와 테스트를 ASan·UBSan으로 직접 빌드해 정상·오류·변형 세 묶음을 실행했다. 링크한 기존 설치 iiJson 정적 라이브러리 자체는 해당 명령에서 계측하지 않았다.
- 기존에 빌드된 iiActorObject 출력 라이브러리와 새 판독기를 결합한 별도 네이티브 테스트에서 골격 및 여러 메시의 모프 애니메이션 GLB의 모든 접근자를 읽었다. 이 검사는 편집 가능한 에셋의 왕복 변환을 증명하지 않는다.
- 설치된 iiJson 헤더와 현재 워크스페이스 iiJson 헤더 각각에 대해 판독기 소스의 C++23 문법 검사를 수행했다. 이는 두 iiJson 버전 모두와의 설치·런타임 호환성을 증명하지 않는다.

## 프로젝트 구성과 설치 소비자

- macOS arm64 Release에서 NSCharacter 포함 라이브러리와 판독·애니메이션 테스트 대상을 빌드했다. 판독 정상·오류 CTest 2건과 애니메이션 네이티브·독립 판독 CTest 2건이 통과했다. 당시 생성된 CTest 목록에는 변형 검사가 포함되지 않아 빌드된 테스트 실행 파일로 2,500건을 별도 실행했다.
- NSCharacter를 제외한 코어 라이브러리와 판독 테스트 대상을 빌드했고 정상·오류·변형 CTest 3건이 통과했다. 두 구성의 라이브러리는 직접 동적 의존성에 Qt가 없었다. 코어 전체 재컴파일에서는 변경하지 않은 `Object3DPoseMorphs.cpp`의 기존 초기화 경고 2건이 나타났다.
- `build/` 아래 별도 스테이징의 NSCharacter 포함 설치본을 사용하는 독립 소비자를 빌드하고 새 GLB 판독 API 호출 테스트를 통과했다. 전역 설치본은 변경하지 않았다.

CC5·Blender·Unreal 등 실제 앱 및 사용자용 명령행 도구는 실행하지 않았다.
