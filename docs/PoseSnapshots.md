# 공용 포즈 방향과 교환용 기준 포즈 스냅샷

## 소유권과 목적

`PoseAiming.h`와 `Object3DPoseSnapshot.h`의 연산은 iiActorObject 본체 기능이다. NSCharacter 없이 정적 메시·소품·임의 골격에 사용할 수 있다. 지속되는 결과 에셋은 `Object3DEngine`이 소유한다. `createObject3DPoseSnapshot`과 `createAimedObject3DPoseSnapshot`은 원본 핸들과 같은 엔진에 새 결과를 등록한다. 실패하면 새 에셋이나 편집 이력을 남기지 않는다.

이 스냅샷은 지정한 포즈의 중립 형상과 모프 보간을 새 기준으로 만드는 교환용 파생 에셋이다. 원본 파라미터·편집 세션·리그를 유지한다. 여러 본의 혼합 스킨에서 이후 임의의 애니메이션까지 동일하게 만드는 연산은 아니며, 리그 프로그램의 기준 좌표와 모션을 자동으로 재타깃하지 않는다. CC5 T 포즈·MetaHuman 제작 리그의 완성은 실제 앱 캘리브레이션과 별도로 검증해야 한다.

## 후손 기준 방향 연산

`aimPoseJoint`는 본과 그 후손을 잇는 방향을 오브젝트 좌표계의 목표 방향에 맞추는 새 로컬 변환을 반환한다. 직접 부모·자식 사이에 helper·twist 본이 있어도 원본 ID·부모·중간 로컬 변환을 유지한다. 본의 로컬 위치·스케일과 입력 포즈의 revision도 변경하지 않는다. 반환값을 적용할지는 호출자가 결정한다.

현재 방향과 목표 방향을 부모 좌표계에서 맞추므로 비균일 스케일과 반사 부모도 처리한다. 반대 방향 근처에서는 외적의 축을 기준 방향에 직교하게 보정하고 매우 작은 반대 방향에는 안정적인 수직 축을 선택한다. 영벡터·비유한 방향·잘못된 후손과 조상 방문 상한을 검사한다. 인체 역할·방향·손바닥의 규칙은 인체 계층의 책임이다.

## 형상·모프·법선 보존

`bakeObject3DPoseSnapshot`은 본체 에셋을 읽고 새 입력 DTO를 반환한다. 입력 로컬 변환 수는 원본 본 수와 같아야 한다. 원본 본 ID·부모·의미, 점·레이아웃·폴리곤·UV·작성된 삼각분할·모프 레코드의 원본 타깃 ID를 유지한다. 미사용 점·UV·법선과 스킨 영향 수를 압축하지 않는다. 사용하지 않는 무가중치 helper 점은 원본 위치를 유지한다.

작성된 선형·DQ·점별 혼합 스키닝은 같은 코어 런타임 계산으로 굽고 프로필을 보존한다. DQ 계산의 전단·특이 배율 제한과 기준 모프를 포함하는 계약은 [변형 스냅샷](DeformationSnapshots.md)을 따른다.

`createOrientedObject3DPoseSnapshot`은 방향과 [관절 프레임](PoseFrames.md)을 하나의 본체 임시 포즈에 적용한다. 모든 방향을 먼저 적용한 뒤 프레임을 순서대로 적용하고 결과 에셋을 한 번만 등록한다. 기존 방향 전용 함수는 프레임이 없는 같은 경로를 사용한다. `maximumJointAims`는 두 목록의 합계에 적용한다.

점별 스킨 가중합을 중립 위치와 모든 모프 위치 델타에 함께 적용한다. 점별 가중 법선 행렬을 A, 중립 법선을 n, 모프 델타를 d라고 하면 새 기준은 `A*n / length(A*n)`, 델타는 `A*d / length(A*n)`이다. 같은 분모를 사용하여 여러 모프의 중간 가중치에서도 방향을 보존한다. 영벡터가 되는 가중 법선과 비유한 결과는 오류이다.

서로 다른 점의 스킨 영향 때문에 같은 원본 법선 ID에서 다른 기준 법선이 필요하면 새 법선 그룹을 덧붙인다. 기존 법선 배열과 미사용 ID는 유지한다. 자동 파생 모프 법선은 해당 교환 시점의 명시적인 레이아웃 법선 델타로 바뀐다. 같은 이름의 여러 원본 레코드는 원래 런타임의 합산·법선 파생 순서를 보존한다.

## 예산과 오류

점·레이아웃·희소 위치/법선 델타·실제 영향 방문·추가 법선 그룹을 각각 제한한다. `maximumDeltas`는 위치 레코드와 결과의 명시적 법선 델타를 합친 상한이다. 목표 방향 목록은 `maximumJointAims`, 각 후손 경로는 `PoseAimOptions::maximumAncestorVisits`를 따른다. 예산은 결과 품질을 낮추는 절단 기준이 아니라 오류 기준이다. 원본 에셋과 엔진의 수명을 연장하지 않는다.

## 검증 범위

단위 검사는 렌더 메시·작성용 토폴로지·원본 ID·여러 모프 중간 가중치·14개 스킨 영향·자동 법선·반사·법선 상쇄·실패 원자성·파일 저장/복원·정적 오브젝트·여러 메시·엔진 소멸을 포함한다. 대형 인체 검사는 기존 표면 맞춤 인체 fixture의 전체 성인·아동을 사용한다. 별도 참조 덤프와 실제 Blender는 전체 원본 점·모프 키·스킨 영향·본 이름과 부모를 확인한다. Blender 검사는 모프 법선 방향을 확인하지 않으며 해당 법선은 native 수치 검사로 구분한다.

자체 프로젝트는 숫자 본 ID를 보존한다. 일반 FBX 재입력은 기존 가져오기 구현의 부모 우선 배열을 사용하므로 이름·부모·스킨 대응 및 수치로 비교한다. 현재 후보의 원래 TDD·수치 검증은 `build/pose-snapshot-prototype/`와 `build/pose-aim-prototype/`에 보존한다. 정식 API의 빌드·설치·앱 검증 결과는 별도 정본 보고서로 확정한다.

## 실행 예제

`iiActorObjectPoseSnapshot`은 NSCharacter 없는 코어에서도 빌드되는 C++23 예제이다. 본 이름과 후손 이름·오브젝트 방향을 5개 인수 단위로 받고, 본체에서 방향 계산과 기준 포즈 스냅샷을 만든 뒤 FBX로 저장한다. 별도 출력 경로를 요구하며 입력 파일을 덮어쓰지 않는다. 입력 바이트·관절 목록 예산과 유한 숫자를 검사한다.

입력과 출력의 정규 경로가 같은 경우와 실제 파일이 같은 경우를 모두 거부한다. 심볼릭 링크와 서로 다른 이름의 하드링크도 포함한다. 회귀 검사는 고정된 인체 원본을 복제한 시험 파일에서만 별칭을 만들며, 같은 경로·하드링크·심볼릭 링크·잘못된 인수와 정상 출력을 확인한다. 거부된 인수는 기존 출력도 변경하지 않는다.

```sh
build/iiActorObjectPoseSnapshot input.fbx build/reference-pose.fbx \
  upperarm01.L lowerarm01.L 1 0 0 lowerarm01.L wrist.L 1 0 0 \
  upperarm01.R lowerarm01.R -1 0 0 lowerarm01.R wrist.R -1 0 0
```

실제 성인·아동 시험은 이와 별도로 인체 역할 어댑터 경로도 사용한다. 원본 이름을 직접 사용하는 예제와 역할 어댑터의 성인 결과를 바이트로 비교하여 역할 대응과 공용 생성 경로의 일치를 확인한다. 명시한 팔 방향을 실제 앱의 전신 T 포즈 캘리브레이션 완료로 표시하지 않는다.

## 2026-10-27 정본 검증

동일한 정본 소스에서 다음 검사를 통과하였다. 실패·건너뜀은 0이다. NSCharacter 포함 구성은 이번 변경에 관련된 선별 검사이며 전체 NSCharacter 묶음을 다시 실행한 결과는 아니다. 이전 577회 본 대응·거리 검증 스냅샷과 그 소스·라이브러리·산출물은 변경 전에 별도 보존하였다.

| 구성 | SDK 검사 | 별도 설치 소비자 |
| --- | --- | --- |
| Release, NSCharacter 포함 | 새 경로 33/33 및 기존 소유권 4/4 | 관련 선별 3/3 |
| Release, NSCharacter 제외 | 전체 253/253 | 전체 4/4 |
| Release, NSCharacter·DNA 제외 | 전체 231/231 | 전체 3/3 |
| Debug 정적, ASan·UBSan | 관련 선별 34/34 | 관련 선별 3/3 |

합계 568개 CTest 실행이다. 기존 정적 구성은 예제 빌드가 꺼져 있으므로 CLI 예제 검사는 Release에서 수행하였다. 초기 검증 스크립트가 정적 구성에도 CLI 파일을 요구했던 실패 기록을 보존하고, SDK 검사를 다시 시작하지 않은 채 남은 정적 설치·소비자 단계를 이어서 완료하였다. 정적 SDK·인체·Blender 검사는 모두 통과하였다.

두 구성의 일반 포즈 스냅샷과 인체 역할 방향 각각에 전체 성인·아동 입력을 적용하였다. 입력마다 본 163개·메시 5개·원본 점 43,474개·모프 채널 296개를 유지하였다. native는 5개 모프 가중치 패턴의 위치·법선을 비교하며 인체 경로는 네 팔 방향·중간 본·원본 ID·부모를 함께 확인한다. 원본 이름을 사용하는 Release CLI와 인체 역할 경로의 성인 FBX가 바이트까지 일치하였다.

실제 Blender 4.5.9 LTS에서 총 8개 FBX를 가져와 모든 원본 점·모프 키·스킨 영향·본 이름과 부모를 확인하였다. 중립과 두 가지 모프 중간 가중치 패턴의 최대 점 위치 오차는 2.5204253e-06m, 최대 스킨 가중치 오차는 2.9787262e-08이다. 이 앱 검사에서 모프 법선·전신 T 포즈 캘리브레이션·포즈 의상 간격을 완료하였다고 표시하지 않는다.

소스·라이브러리·설치 헤더·산출물 해시와 상세 범위는 [정본 포즈 스냅샷 검증 보고서](PoseSnapshotVerification-20261027.json)에 기록한다. 코어 전용 설치에는 NSCharacter 헤더·심벌이 없고 네 구성에 Qt 심벌이 없다.

위 568회는 방향 전용 단계의 역사적 스냅샷이다. 이후 프레임 연산과 인체 손 기준을 추가한 정본에서는 [관절 프레임의 구성별 검증](PoseFrames.md)에 기록한 609회가 통과하였다. 새 `PoseSnapshot.fbx`는 손 프레임을 포함하며 방향 전용 CLI는 별도 `ArmDirections.fbx`와 비교한다. CLI는 동일 경로·하드링크·심볼릭 링크를 통한 입력 덮어쓰기도 거부한다. 현재 상세 해시는 [관절 프레임 보고서](JointFrameVerification-20261027.json)에 보존한다.

[기준 자세 프로그램](PoseReference.md)이 있는 에셋은 `createReferenceObject3DPoseSnapshot`으로 캐시의 자세를 별도 교환 에셋에 굽는다. 모든 명시적 포즈 스냅샷은 원본의 기준 프로그램을 제거하여 초기 자세가 두 번 적용되지 않게 한다. 원본 에셋과 리그의 바인드는 유지한다. 방향 계산도 로컬 후손 경로를 합성하여 큰 원점의 월드 위치 상쇄를 피한다.
