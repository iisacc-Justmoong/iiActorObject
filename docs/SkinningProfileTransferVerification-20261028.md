# 스키닝 프로필 전사 검증

2026-10-28 macOS arm64에서 C++23 코어 전용 구성과 NSCharacter 포함 구성을 검사했다. 두 구성에서 `IIACTOROBJECT_VALIDATE_APPLICATION_EXECUTION`은 `OFF`이다. 사용자의 지시에 따라 CC5·Blender·Unreal 등 실제 앱과 사용자용 CLI는 실행하지 않았다.

## 구현 범위

`iiActorObject`는 원본 점이나 최근접 표면을 통해 본 가중치와 함께 선형·듀얼 쿼터니언(DQ)·점별 혼합 프로필을 전사할 수 있다. NSCharacter는 본체 엔진의 에셋과 편집기를 참조하고 이 기능에 위임한다. 새 전사 정책은 `PreserveTarget`, `Source`, `SourceIfNonlinear`이다. 기존 일반 표면 전사와 대칭 전사 호출은 대상 프로필을 유지한다. 기존 템플릿 리그·적응 호출은 DQ·혼합 원본을 적용하고 선형 원본에는 기존 대상 프로필을 유지한다. 선형 원본도 명시적으로 복사하려면 `Source`를 사용한다.

동일 토폴로지에서는 원본 점 ID를 사용한다. 다른 토폴로지에서는 본 가중치와 동일한 삼각형과 무게중심 좌표로 혼합값을 계산한다. 선택하지 않았거나 거리 조건에서 건너뛴 대상 점은 기존 값을 보존한다. 대칭 평면의 교차점에는 원래 변에서 보간한 값을 사용한다. 부분 전사에 순수 방식이 섞이면 점별 혼합 프로필로 표현한다. 편집기 이력·레이어와 네이티브 프로젝트 저장 경로를 이용하며, 템플릿 적응이 추가한 숨은 보조점의 혼합값은 0으로 초기화한다.

## 확인한 결과

- 표면 전사·대칭·편집 7/7, 템플릿 리그 전사 6/6, 템플릿 적응 8/8, DQ 변형·프로필 회귀 10/10, 기존 표면 ABI 1/1이 두 구성에서 각각 통과했다. 기존 `SkinTransferOptions` 크기와 호출 기호는 별도로 검사했다.
- 과거 프로젝트 버전 1~8, 레이어, 스냅샷, 손상 복원과 런타임 경로 12/12가 두 구성에서 각각 통과했다.
- `build/` 내부의 별도 설치 경로에 있는 공개 헤더와 라이브러리를 사용하는 소비자 검사는 두 구성에서 각각 2/2 통과했다. 이 검사는 회전한 대상의 리그 등록·DQ 프로필 전사와 기존·추가 API를 사용한다. `~/.local` 설치본은 갱신하지 않았다.
- 두 공유 라이브러리의 직접 동적 의존성은 C++ 표준 라이브러리와 macOS 시스템 라이브러리이다. Qt는 관찰되지 않았다.

## 남은 제한

최근접 표면 전사는 유사한 기준 자세와 정렬을 전제로 하며 가까운 다른 신체 부위에 잘못 연결될 수 있다. 일치하는 점 ID를 사용하는 경우 ID가 같은 의미인지 호출자가 보장해야 한다. 템플릿 적응의 별도 follower `transferSkin`은 본 가중치만 전사하며 DQ 프로필은 별도로 전사해야 한다. 비선형 프로필의 GLB·DNA 출력과 DQ 포즈·모프 스냅샷은 구현되지 않아 해당 경로는 거부한다.

이 작업은 CC5·Blender·Unreal에서의 실제 동작이나 MetaHuman과 동등한 데이터 계약, 제작용 얼굴·인체 품질을 입증하지 않는다. 플랫폼별 빌드, 추가적인 캐릭터 기능 및 이들 형식의 호환 작업은 전체 목표에 남아 있다.
