# FBX 애니메이션 출력 검증 — 2026-10-28

## 범위

본체 `exportObject3DFbx(asset, clip, options)`의 골격 위치·XYZ 오일러 회전·스케일, 명시적인 이름 일치 모프 곡선 출력과 입력 제한을 검사했다. 애니메이션이 없는 기존 FBX 출력은 별도 오버로드로 유지한다. SDK의 FBX 애니메이션 가져오기는 구현하지 않았으며, 대상 앱이나 사용자용 CLI를 실행하지 않았다.

## 결과

- 테스트를 먼저 작성해 새 API가 없을 때 컴파일이 실패함을 확인했다. 이후 네이티브 검사에서 같은 골격 객체·동적 변형 바인드·스칼라 연결 및 손실 선택·샘플 예산·비유한 옵션·FBX 시간 충돌·범위를 넘는 값·소실되는 스케일을 검사했다. 출력 결정성과 기존 정적 오버로드의 일치도 확인했다.
- 독립 Python FBX 7.4 이진 파서가 animation stack·layer·곡선 노드와 속성 연결, signed 64비트 시간, 선형 보간 속성과 키의 시작·끝·최대 간격을 확인했다. 골격 세 본과 두 메시의 같은 이름 표정 채널을 확인했다. 별도의 표정 전용 클립은 -0.5~1.5 값을 클램프하지 않고 0.25초 이전과 1.75초 이후를 유지했다.
- SDK 가져오기 코드를 사용하지 않는 별도 MIT ufbx 판독기가 양·음의 회전 특이점을 다루는 두 시료 각각에 대해 2초 동안 201개 시점에서 각 본의 이동·스케일·회전과 두 모프 채널을 평가했다. 부모 ID가 자식 ID보다 큰 계층, 180도 경계, 다른 축 회전을 포함한 +90도와 -90도 특이점을 통과했다. 두 시료의 세 본 전체에서 측정한 최대 회전 차이는 `0.000291215`라디안이었고 이 테스트 설정의 검사 오차는 `0.0005`라디안이었다. 표정 전용 클립도 같은 판독기로 검사했다. 이는 합성 시료의 유한 시점 결과다.
- 공유 구성에서 관련 회귀 17개가 통과했고 이후 보강한 표정 전용·텍스트 전달 검사를 포함한 새 검사 2개가 다시 통과했다. `IIACTOROBJECT_WITH_NSCHARACTER=OFF`와 DNA 활성 코어 구성에서도 같은 관련 회귀 17개가 통과했다. 두 구성은 `IIACTOROBJECT_VALIDATE_APPLICATION_EXECUTION=OFF`이며 앱 실행 제외 등록 정책 검사도 포함한다.
- `build/` 아래에 별도로 설치한 공유·코어 SDK의 C++23 소비자 두 개가 새 애니메이션 출력 API를 호출했다. 시스템과 사용자 설치본은 변경하지 않았다. 두 공유 라이브러리의 macOS 동적 의존성에서 Qt는 나타나지 않았다.

## 남은 일

FBX animation take의 입력과 다시 편집하는 경로, 비선형·constraint·재질 곡선, 여러 클립, 실제 제작 리그와 사용자 에셋의 충실도는 이 결과에 포함되지 않는다. CC5·Blender·Unreal을 실행하거나 가져오지 않았으므로 이 결과는 이들 앱의 실제 호환성이나 MetaHuman 품질의 입증이 아니다. 회전 오차 제한은 지정한 키와 각 구간의 분할 검사점에만 적용되며 연속 구간 전체의 보장은 아니다.
