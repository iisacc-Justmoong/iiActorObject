# FBX 작성용 구조와 교환 계약

## 목적과 본체 경계

FBX의 제어점·사각형·UV 경계·원본 모프 레코드를 유지하여 모델을 다시 편집하기 위한 본체 기능이다. 저장소와 연산은 `iiActorObject`에 있으며 NSCharacter의 FBX 함수는 이를 참조한다. C++23·표준 라이브러리와 고정된 MIT ufbx를 사용한다. Autodesk SDK나 Qt에 의존하지 않는다.

입력은 노드 인스턴스별 하나의 작성용 메시이다. 여러 머티리얼이 있어도 메시를 분할하지 않는다. 좌표는 노드의 geometry 변환과 파일 단위·축을 적용한 오브젝트 공간의 Y-up·미터이다. 원본 노드·피벗·인스턴스 그래프를 복원한 프로젝트 형식이 아니다. 메시·스킨·기준 골격의 편집 스냅샷이다. 입력과 대상의 좌·우수 좌표계가 다를 때 ufbx의 X 거울 축을 명시해 메시·관절 변환과 winding을 함께 변환한다. 이때 SDK 편집 메타데이터의 원본 코너 순서와 모프 법선도 변환된 표준 FBX 자료와 같은 좌표계에서 검증하며, 원본 접선의 코너 순서와 handedness를 보정한다. 이전 버전에서 음의 루트 스케일로 위·앞 방향이 반전되어 가져온 에셋은 원본 FBX에서 다시 가져와야 한다.

## 자료와 ID

`Object3DMesh::topology`가 원본 제어점과 작성용 연결을 보관한다. 위치·UV·법선의 분리 인덱스와 사용하지 않는 제어점·속성을 유지한다. 원본 폴리곤을 삼각형으로 바꾸지 않고 `MeshTopologyDefinition::polygons`에 보관하며, 렌더 삼각형만 별도로 계산한다. UV·법선 값이 같아도 서로 다른 원본 속성 ID를 합치지 않는다.

`MeshTopologyLayout::trianglePolygons()`는 렌더 삼각형에서 원본 폴리곤 ID로 가는 대응이다. `polygonMaterials`는 각 원본 폴리곤의 전역 머티리얼 ID이며, 비어 있으면 `Object3DMesh::material`을 사용한다. 파생 `Object3DMesh::triangleMaterials`는 삼각형별 ID이다. 본체가 캐시를 만들고 머티리얼 범위와 개수를 검사한다. 작성용 자료가 없는 메시도 `triangleMaterials`를 직접 사용할 수 있다. 이 값의 비파괴 편집은 기존 보정 계층에 보관한다.

FBX 출력은 작성용 폴리곤과 제어점을 사용한다. UV·법선은 IndexToDirect 형식으로 작성하여 경계와 사용하지 않는 원본 속성을 유지한다. GLB는 같은 정점·스킨·모프 accessor를 공유하는 머티리얼별 primitive를 작성한다. GLB는 렌더 결과의 교환이며 원본 사각형·숨김 face·작성용 ID의 보존 형식이 아니다.

## 재질 표면 설정

[재질 표면 계약](MaterialSurface.md)의 알파 방식·임계값·양면 여부와 원본 기본색 알파는 필요한 경우 SDK 전용 FBX 머티리얼 속성으로 보존한다. `Opaque`의 표준 FBX 불투명도는 1로 출력하며 원래 알파는 별도 속성에 기록한다. SDK 재입력은 네 속성이 모두 유효할 때 복원하고 불완전하거나 잘못된 확장을 거부한다. 표준 불투명도가 확장과 다르면 기본 가져오기를 거부해 외부 수정값을 조용히 덮지 않는다. 작성용 보조 자료 복원을 끄면 재질 확장도 무시하고 표준값을 사용하며 경고한다. 표준 FBX 불투명도는 알파 마스크 임계값이나 양면 셰이더와 동등하지 않으며 다른 앱의 해석과 재출력은 검증하지 않았다.

## 스키닝 방식

선형, 듀얼 쿼터니언, 점별 선형·DQ 혼합을 FBX 스킨 디포머의 `SkinningType`과 `Indexes`·`BlendWeights`로 읽고 쓴다. 모든 작성 점의 혼합값을 기록하며 누락된 입력 점은 0으로 처리한다. 중복·범위 밖 인덱스, 비유한 값, 불완전하거나 길이가 다른 배열, 방식과 모순되는 값을 거부한다. 정적 에셋에는 FBX 스킨 디포머가 없으므로 비선형 프로필 출력은 거부한다. FBX 기능 지원과 대상 앱에서 동일하게 작동하는지는 별개의 문제이다.

## 숨김 면과 확장 정보

표준 FBX geometry에는 보이는 폴리곤만 작성한다. 숨긴 관절·의상 보조 표면이 외부 앱에 실제 면으로 표시되지 않게 하기 위함이다. 모든 원본 제어점은 표준 `Vertices`에 남기므로 외부 앱에는 사용하지 않는 정점이 있을 수 있다.

geometry의 `iiActorObjectTopology` 버전 1 확장은 다음 자료를 보관한다.

- 원본 형식·메시 ID, 위치·UV·법선 수와 winding이다.
- 모든 layout과 폴리곤, 원본 그룹·머티리얼·숨김 face, 렌더 대응이다.
- 빈 원본 스킨 행의 제어점 ID이다. 정적 객체의 묵시적 루트 바인딩과 원본 빈 행을 구분한다.

큰 정수 목록과 그룹은 하나의 raw blob으로 보관한다. 정수는 little-endian uint32이며 그룹은 uint32 길이와 UTF-8 바이트의 연속이다. ufbx는 수정하지 않고 retained DOM의 원시 값을 읽는다. 임의 파일 경로나 실행 코드를 포함하지 않는다.

복원 시 속성 수·보이는 폴리곤의 코너 대응·머티리얼 슬롯·빈 스킨 행을 실제 표준 FBX와 대조한다. 맞지 않는 확장 자료를 조용히 적용하지 않는다. 외부 앱에서 연결·UV 인덱스·스킨을 바꾸어 확장이 낡았다면 기본 복원은 실패한다. 호출자가 `FbxImportOptions::restoreAuthoringMetadata=false`를 지정하면 현재 표준 FBX 구조로 읽고 경고를 받는다. 외부 앱이 이 확장을 삭제하거나 재정렬한 뒤에도 원래 작성용 ID가 보존된다고 주장하지 않는다.

## 스킨과 모프

스킨은 원본 제어점에 저장하며 영향 수를 4개나 8개로 절단하지 않는다. 스킨이 없는 부착 메시는 가장 가까운 본 조상 또는 루트로 강체 바인딩한다. 스킨에 남은 빈 행은 원본에서 빈 상태로 보존하고 렌더 시 본체의 루트 규약을 따른다. 음의 geometry scale에서는 winding과 역전치 법선을 함께 처리한다.

작성용 모프는 원본 제어점 위치 델타와 target ID를 사용한다. 일반 보존용 FBX는 blend channel의 `iiSourceName`·`iiSourceTarget`에 원래 논리 이름과 ID를 보관하고, 같은 이름의 여러 레코드를 `_SourceN`으로 구분한다. SDK 재입력은 논리 이름과 원본 ID를 복원한다. 외부 편집용 문서 토큰을 지정한 FBX는 이와 달리 같은 이름의 레코드를 하나의 표준 채널로 투영한다. 원본 분할은 FBX에 없으므로 원본 프로젝트와 함께 사용한다. [논리 모프 계약](LogicalMorphChannels.md)을 따른다.

모프의 명시적 법선은 원본 layout ID에 보관하며 위치에서 계산하는 법선과 구분한다. 표준 FBX Shape의 제어점 법선 델타를 변환·보존하고, 경계 양쪽에 서로 다른 델타가 필요하면 기본 출력은 거부한다. `FbxExportOptions::allowMorphNormalMetadata=true`는 표준 투영과 정확한 SDK 확장 자료를 함께 출력한다. 확장 미복원 시 투영 손실을 경고한다. 계산형·명시형·빈 명시형과 비균등 스케일의 규약은 [모프 법선 계약](MorphNormals.md)에 있다. [FBX 탄젠트 계약](FbxTangents.md)은 UV별 기준 기저와 폴리곤 투영 한계를 설명하며, 연결된 원본 탄젠트는 기준 상태와 함께 보존하고 모프 탄젠트 보존은 남아 있다.

원본 DNA를 가져와 상세 편집한 뒤 이 SDK의 FBX를 경유하면 source format·메시 ID·layout·폴리곤·target ID를 복원하여 기존 RigLogic 세션을 새 에셋에 연결하고 DNA로 저장할 수 있다. 이 경로는 SDK의 확장이 유지된 경우이다. Blender·CC5·Unreal의 재출력에 대해 같은 원본 ID 복원을 보장하는 근거가 아니다.

## 입력 제한과 미지원 자료

기본 제한은 파일 256 MiB, 전체 제어점과 렌더 정점 각각 200만 개, 본 4,096개, 메시별 모프 4,096개, 폴리곤 200만 개, 코너 800만 개이다. 파서는 기존과 같이 파일 제한의 네 배까지 임시·결과 메모리를 제한한다. 작성용 인덱스·코너·확장 blob도 별도로 검사한다.

각 면은 3~256개 코너의 단순 폴리곤이어야 한다. 빈 보조 mesh는 경고 후 제외한다. [여러 UV 세트](MultipleUvSets.md)는 세트별 seam과 이름을 보관한다. 외부 텍스처와 내장 PNG 외 이미지는 [호스트 이미지 해석기](FbxImageResolution.md)를 통해 제공할 수 있다. 입력의 정점 색·애니메이션 take·앱 제약·geometry cache는 현재 편집 프로필의 범위 밖이며 경고로 구분한다. 별도의 [FBX 애니메이션 출력](FbxAnimation.md)은 골격과 명시적으로 연결한 모프 곡선을 작성하고, [애니메이션 포함 가져오기](FbxAnimationImport.md)는 여러 테이크의 본·모프 표본을 반환한다. 여러 스킨 디포머·지원하지 않는 스키닝 방식·progressive morph·표현 불가능한 본 shear는 거부한다. 원본 앱의 모든 FBX 기능을 복원한 것으로 해석하지 않는다.

## 검증과 남은 적용

네이티브 검사는 UV seam, 원본 ID·사용하지 않는 속성·숨김 면·빈 스킨 행·동일 이름의 복수 target ID·면별 머티리얼·정적 메시·음의 scale·낡은 확장 거부를 확인한다. 독립 ASCII FBX에서 사각형과 사용하지 않는 점을 읽는 검사도 포함한다.

별도 DNA reader로 DNA→편집→FBX→SDK→DNA의 위치·연결·기준 골격·behavior를 검사한다. 실제 Blender에서는 FBX 제어점·사각형·머티리얼·shape key·스킨을 검사하고, 인체 FBX의 제어점 19,158개와 사각형 13,378개가 보존되는지 확인한다. CC5·Unreal의 실제 characterization·애니메이션·재출력과 제작용 MetaHuman 적용은 별도 완료 조건이다.
# FBX 관절 행렬의 수치 허용값

`FbxImportOptions::maximumJointMatrixError`의 기본값은 기존과 같은 `1e-7`이다. SRT로 재구성한 관절 행렬과 입력 행렬의 각 원소 차이를 `max(1, abs(input))`로 나눈 최대값을 사용한다. Blender의 float 계산을 거친 파일처럼 작은 수치 오차가 있는 경우 호출자가 명시적으로 `1e-6` 등을 선택할 수 있다. 유한한 0~`1e-3` 범위만 허용하며 그 범위를 넘는 실제 전단은 계속 거부한다.

`Object3DImport::maximumJointMatrixError`는 실제로 관측한 최대 오차이다. 기본 허용값을 넘는 재구성을 수락하면 관절 이름과 최대 오차를 warnings에 한 번 기록한다. 임의 전단을 SRT로 조용히 바꾸지 않으며, 범위 밖 행렬·잘못된 옵션은 본체에 자산을 등록하기 전에 실패한다. `FbxImportPrecisionTest`가 기본 거부·명시적 수락과 진단·실제 전단 거부·실패 원자성을 검사한다.


[얼굴 부속·이미지 연결](FaceAssets.md)의 PNG 불변 자료·눈·치아·혀·작성된 점 대응도 본체 소유이다. NSCharacter는 로딩 중의 인체 의미 해석과 본체 핸들만 가진다. 선택적인 `MakeHumanTemplateOptions::faceAssets`로 공식 CC0 별도 패키지를 지정한다. 실제 GLB·FBX의 이미지 바이트·재질 연결·점 위치와 눈·턱의 스킨 변형은 `FaceAssetsVerification-20261027.json`에 기록한다.

[기준 자세 프로그램](PoseReference.md)이 있는 정본은 프로그램의 의미를 누락시키지 않도록 직접 FBX 출력 시 오류이다. `createReferenceObject3DPoseSnapshot`으로 별도 교환 에셋을 만든 뒤 출력하며, 원본 편집 자료와 리그는 보존한다.


[메시의 기본 모프 값](DefaultMorphWeights.md)은 FBX `DeformPercent`로 교환하며, 같은 논리 채널을 구성하는 원본 레코드들의 값이 다르면 가져오기를 거부한다.
