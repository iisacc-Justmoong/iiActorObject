# 리그 제어의 편집 가능한 모프 샘플

`createObject3DRigMorphSamples`는 본체가 소유한 리그와 메시를 이용하여 기준 제어 상태 및 하나 이상의 제어 상태를 새 본체 에셋으로 만든다. 각 상태의 관절·블렌드셰이프가 결합된 변형을 독립적인 모프 끝점으로 기록한다. `NSCharacter::createCharacterRigMorphSamples`는 같은 본체 에셋을 참조하는 인체 뷰에 대한 편의 함수이다. 엔진, 에셋, 리그 프로그램과 실행 버퍼는 본체가 소유한다.

## 입력과 실행

기준과 각 타깃에 Raw 또는 GUI 제어 공간과 이름별 값을 지정한다. 지정하지 않은 항목은 드라이버의 해당 공간 기본값으로 채운다. 중복·없는 이름, 비유한 수치, 잘못된 LOD와 이름 충돌을 거부한다. 호출은 상태마다 독립된 드라이버 복제본을 만들며 원본 세션을 평가하거나 수정하지 않는다. 교체 가능한 드라이버는 `clone()`이 독립적인 가변 실행 상태를 제공해야 한다. 본체는 입력과 실행 작업량·추가 델타·출처 값의 상한을 검사한다. 출처 이름의 총 바이트 한도는 실행 버퍼 복제 전에 확인하며, 실패 시 결과 에셋을 등록하지 않는다.

기준 상태는 자세와 기존 블렌드셰이프를 함께 구운 별도 에셋이다. 새 모프의 값이 0이면 기준 상태, 해당 모프 하나만 1이면 그 상태의 메시 위치와 법선이다. 기존 모프는 기준에 대한 추가 변위로 남는다. 새 끝점 여러 개를 동시에 혼합하는 것은 형상의 선형 보간이며 비선형 리그 프로그램을 다시 계산하는 것과 같다는 뜻은 아니다. 기준 형상은 에셋 유효성 규칙을 만족해야 한다. 이후의 끝점은 런타임에서 가능한 접힘도 보존할 수 있다.

작성용 토폴로지가 있으면 원본 포인트 ID, 레이아웃과 UV·법선 분리, 사용하지 않는 포인트 및 속성을 유지한다. 포인트 위치와 명시적인 레이아웃별 법선 델타로 각 타깃을 표현한다. 렌더 전용 메시에도 위치와 법선 타깃을 추가한다. 부분 관절 리그는 입력 에셋의 기준 자세 위에서 적용한다. 소스 리그의 제어 순서·기본값, LOD, 관절 대응, 입력, 출력 블렌드셰이프·애니메이티드 맵 및 원본 본 순서의 로컬 포즈는 `rigSampleCatalogs`에 보존한다.

원본 포인트와 렌더되지 않는 법선도 작성된 선형·듀얼 쿼터니언·점별 혼합 프로필로 평가한다. 혼합값은 원본 포인트 ID를 기준으로 하며 UV 이음새와 별도 법선 레이아웃에서도 동일하다. 본 가중치가 없는 비표시 포인트는 원래 공간을 유지하고 표시 포인트는 루트 본을 따른다. 원본 포인트와 미사용 법선에 대한 듀얼 쿼터니언 영향 검색과 혼합 작업은 샘플 작업량 제한에 포함한다.

기존 호출은 스킨 프로필을 보존한다. GLB처럼 비선형 스킨을 표현할 수 없는 포맷에 사용할 때는 추가 인자를 지정할 수 있다. 기준과 요청한 개별 끝점은 바인드 자세에서 원본 평가와 일치하지만, 다른 자세의 애니메이션이나 여러 모프의 동시 혼합까지 원본 비선형 스키닝과 일치하는 것은 아니다.

```cpp
const auto result = iiActorObject::createObject3DRigMorphSamples(
    rig, baseline, samples, {},
    iiActorObject::Object3DSnapshotSkinning::LinearizeAtBind);
```

`NSCharacter::createCharacterRigMorphSamples`에도 같은 인자를 제공할 수 있다. 선택하지 않으면 `Preserve`이다. 기존 옵션 구조와 기존 호출은 그대로 유지한다. 현재 명령행 도구는 보존 방식만 제공하며 명시적 선형화는 C++ API에서 선택한다.

## 저장과 의미

메타데이터는 **샘플 생성 당시의 출처 기록**이다. 이후 메시나 모프를 수정하면 출처와 현재 형상은 달라질 수 있으며, 이는 실행 가능한 리그 그래프나 자동 셰이더 연결이 아니다. `exportRigSampleCatalogsJson`은 파일 I/O 없이 크기 제한된 UTF-8 JSON을 반환하므로 호스트나 에이전트가 별도 파일로 저장할 수 있다.

샘플 자료와 유효성 검사는 `RigSampleCatalogCore.h`, JSON 내보내기는 `RigSampleCatalogExport.h`에 있다. 기존 `RigSampleCatalog.h`와 최상위 통합 헤더는 두 인터페이스를 계속 제공한다. 에셋 등 다른 헤더를 통해 JSON 선언을 간접적으로 가져오던 코드는 내보내기 헤더를 직접 포함해야 한다. `iiActorObjectRigSamples` 예제도 내보내기 헤더를 직접 포함한다. 골격·포즈 계산 모듈은 내보내기 구현이나 엔진에 의존하지 않는다.

이 출처가 포함된 네이티브 프로젝트는 명시적 기준 자세 순서가 없으면 버전 14로, 순서가 함께 있으면 버전 15로 저장한다. 기존 버전의 읽기 및 출처 없는 자료의 버전 선택은 유지한다. FBX는 일반 메시·모프와 함께 SDK 전용 바이너리 메타데이터를 기록하고, GLB는 루트 노드의 `extras.iiObject3D.rigSamples`에 같은 출처를 기록한다. 포맷 메타데이터를 다른 프로그램이 유지하거나 활용하는지에 대한 보장은 없다. 애니메이티드 맵은 수치 기록이며 셰이더나 텍스처를 자동 생성하지 않는다.

FBX 복원 시 출처 메타데이터의 버전·크기·CRC를 확인하며 중복 블록이나 중복 필드는 거부한다. 작성 메타데이터 복원을 끈 경우 출처를 복원하지 않고 경고한다.

## 검증 범위

코어 수치 테스트는 새 모프 끝점과 원본 드라이버 평가 결과, 부분 리그, 독립 복제, 오류와 수명 및 저장 왕복을 비교한다. DQ·혼합 테스트는 숨겨진 원본 점과 법선에 대해 별도 렌더 메시를 런타임 비교 기준으로 사용한다. DNA 검사는 작은 독립 테스트 자료를 사용한다. 이번 작업에서 CC5·Blender·Unreal 앱은 실행하지 않으며 실제 앱 가져오기나 제작용 MetaHuman 자산의 동작을 주장하지 않는다.

비선형 스킨 샘플 오류 수정과 테스트 구성은 [검증 기록](RigSampleSkinningVerification-20261029.md)을 따른다.

사용자용 명령행 도구와 외부 앱의 별도 실행 검증은 명시적으로 요청된 경우에만 수행한다. `IIACTOROBJECT_VALIDATE_APPLICATION_EXECUTION`의 기본값은 OFF이며, 이때 CTest에는 그런 실행 검증이 등록되지 않는다. 필수 자동 단위·통합 테스트와 포맷 검사는 계속 실행한다. 선택 실행 검증의 입력은 `resources/`에서 하드링크하고 임시 입출력을 정리한다. 현재 지침 이전에 시행한 도구 실행 결과는 당시의 기록으로만 보존한다.

## 명령행 인터페이스

SDK 도구 `iiActorObjectRigSamples`는 다음과 같이 입력 DNA 또는 저장된 리그가 있는 프로젝트를 읽는다. `IIACTOROBJECT_BUILD_TOOLS`는 기본적으로 켜져 있으며 예제 빌드 옵션과 독립적이다. 설치하면 `bin/`에 놓이고 공유 라이브러리는 설치 경로 기준 상대 위치에서 찾는다. DNA 기능이 없는 빌드에서는 일반 포즈 리그 프로젝트를 사용할 수 있다. 출력 파일은 기존 파일을 덮어쓰지 않으며 상위 디렉터리는 미리 있어야 한다.

```sh
iiActorObjectRigSamples input.dna output.glb --manifest output.json --lod 0 \
  --baseline raw smile 0.25 --sample Smile raw smile 0.5
```

`--sample 이름 raw|gui` 뒤에 이름과 값 쌍을 여러 개 지정하고 이 옵션을 반복할 수 있다. `--baseline`을 생략하면 Raw 기본값을 쓴다. 프로젝트에서 여러 리그가 있으면 `--rig`로 0부터 시작하는 인덱스를 지정한다. 출력 확장자는 `.ii3dproject`, `.fbx`, `.glb`이다. 프로젝트 출력은 샘플 자산과 선택한 원본 리그를 함께 보관한다. `--manifest`는 선택적인 출처 JSON이다.
