# 편집 가능한 대상 템플릿 검증

2026-10-28 macOS arm64에서 [대상 메시 템플릿화](TemplateAdapt.md)를 C++23 네이티브 코드와 독립 FBX·GLB 파서로 검사했다. 사용자 지시에 따라 CC5·Blender·Unreal과 별도의 사용자용 애플리케이션은 실행하지 않았다.

- 서로 다른 삼각분할의 합성 메시에서 원본 조절·드라이버와 바리센트릭 형상 변위를 대상에 옮겼다. 기준 가중치 0.5에서 입력을 복원하고 조절값을 변경하면 대상 표면과 관절 기준점이 함께 변한다. 변위가 위치에 따라 선형으로 바뀌는 시료에서 새 중앙 점의 보간 결과도 확인했다. UV 경계의 두 렌더 정점은 각각의 UV와 같은 위치 변위를 보존했다. 축별 배율 정렬 시 형상 변위에도 같은 배율이 반영되는지 검사했다. 접지를 적용한 경우와 끈 경우를 구분했으며 편집 undo·redo와 전사된 포즈 프로그램의 새 골격 평가를 검사했다.
- 작성용 토폴로지가 없는 렌더 메시를 승격하고 기존 UV·모프와 새 조절을 유지했다. 잘못된 옵션, 거리·작업 예산 초과, 기존 모프 이름 충돌과 대상 엔진의 템플릿 용량 초과는 실패로 처리하고 생성한 임시 에셋을 제거했다. 원본과 대상이 서로 다른 엔진일 때 원본 엔진 소멸 후에도 새 대상 템플릿을 사용할 수 있었고, 대상 엔진이 소멸하면 참조도 만료되었다.
- 독립 Python 파서는 합성 결과의 FBX BlendShape 연결·모프 위치 변위와 GLB의 이름·희소 POSITION 변위를 확인했다. 이 검사는 앱에서 모프를 가져와 조작했다는 뜻이 아니다.
- 공개 CC0 인체의 렌더 메시를 14,517개 정점에서 41,273개로 재분할하고 작성용 토폴로지로 승격했다. 472개 원본 타깃과 1,117개 관절용 보조점에서 총 1,245,231개의 희소 점 변위를 생성했다. 코 타깃의 기준값 0.4를 대상에 맞춘 뒤 0.7로 변경했을 때 원본의 기존 렌더 정점과 비교한 최대 위치 차이는 이 시료에서 0, 기준 재현 오차는 약 `2.2e-16`, 최대 관절 위치 차이는 약 `6.8e-16` 오브젝트 단위였다. 실제 최대 점 이동은 약 `0.00165`였다.
- 같은 기준에서 상다리 길이 타깃을 0.5로 바꾸는 별도 시료는 접지 규칙을 유지했다. 원본과의 기존 정점 최대 차이는 약 `2.8e-17`, 관절 최대 차이는 약 `8.1e-16`, 최대 점 이동은 약 `0.0534`였다. 독립 FBX·GLB 파서는 41,273개 보이는 정점의 관절 영향과 가중치를 확인했다.

일반 빌드의 신규 검사 9/9와 코어 단독 빌드의 7/7이 통과했다. 신규 검사에는 독립 형식 파서와 프로젝트 저장·복원 후 조절·undo·redo가 포함된다. 관련 템플릿·리그·스킨·스켈레톤·프로젝트·FBX 회귀 검사는 일반 87/87, 코어 단독 85/85가 통과했다. 별도로 `build/` 아래에 설치한 라이브러리를 사용하는 NSCharacter·코어·이미지 코덱 C++ 소비자도 각각 1/1 통과했다. AddressSanitizer·UndefinedBehaviorSanitizer를 적용한 신규 합성·인체 검사는 6/6 통과했으며 macOS에서 누수 검출은 비활성화했다. 확인한 일반 공유 라이브러리의 동적 의존성에 Qt는 없었다. 모든 구성에서 앱 실행 검증은 비활성화했다.

두 인체 변경은 같은 공개 템플릿의 표면을 재분할하여 만든 통제된 입력이다. 임의 스캔, 다른 인체의 근접 표면 대응, 의상·눈·치아의 연동, 큰 자세 차이, 제작용 외형·변형 품질 및 실제 대상 앱의 동작을 보증하지 않는다. 이 기록을 작성한 단계에서는 원본 부속 바인딩과 충돌 맞춤을 전사하지 않았다. 이후 부속 연결의 범위와 검사는 [별도 기록](TemplateFollowersVerification-20261028.md)을 따른다.
