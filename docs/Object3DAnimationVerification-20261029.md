# 본체 애니메이션 변환과 적용 검증: 2026-10-29

이 기록은 GLB 원본 채널을 본체 클립으로 변환하고, FBX의 메시별 모프를 가져오며, 본과 모프를 동일 인스턴스에 적용한 작업의 특정 소스 상태에 대한 것이다. 전체 NSCharacter 목표의 완료를 뜻하지 않는다.

## 확인한 범위

- GLB 원본의 선형·큐빅·선택적 STEP 근사를 편집 가능한 클립으로 표본화하고, 메시별 동일 이름 모프의 서로 다른 값을 인덱스 대응으로 보존했다. STEP의 기본 정책은 거부이며 근사 구간은 결과에서 명시한다.
- GLB에서 변환한 클립을 FBX로 출력하고 `PerMesh`로 다시 읽은 뒤 본체 인스턴스에 적용했다. 별도 GLB 판독과 MIT ufbx 판독은 출력 본과 모프 곡선을 검사했다.
- 공용 클립 적용은 다른 에셋·인스턴스·바인드, 잘못된 곡선·모프 및 중복 대상에 대한 실패 시 포즈와 가중치가 그대로인지 확인했다. 같은 곡선을 여러 메시가 공유하는 경우와 서로 다른 곡선을 사용하는 경우를 검사했다.
- 정적 에셋의 모프만 적용할 때 기존 내부 루트 포즈를 보존했다. 본체 클립 적용과 GLB 원본·베이크 샘플 적용 경로를 각각 확인했다.
- MakeHuman 인체 템플릿의 19,000개 이상의 원본 점과 150개 이상의 본을 사용하는 검사에 별도 테스트용 모프를 추가했다. 이는 MakeHuman의 원본 모프나 제작용 인체 품질을 입증하는 검사가 아니다.

## 실행 결과

모든 항목은 macOS arm64의 C++ 자동 검사이며 대상 앱 실행 옵션은 꺼 두었다.

| 구성 | 범위 | 결과 |
| --- | --- | --- |
| Release, NSCharacter 제외 | 본체 적용, GLB·FBX 애니메이션 변환·입출력, 자세 보정 관련 회귀 | 34/34 통과 |
| Release, NSCharacter 포함 | 위 범위와 큰 인체 GLB 베이크 | 35/35 통과 |
| Debug, NSCharacter 포함, AddressSanitizer·UndefinedBehaviorSanitizer | 적용·변환·FBX 재가져오기와 큰 인체 검사 | 15/15 통과 |
| 별도 설치 경로의 SDK 소비자 | 코어 전용 및 NSCharacter 포함의 GLB·FBX 각 2건 | 4/4 통과 |

AddressSanitizer의 누수 검사는 비활성화했으므로 누수 검증 결과는 포함되지 않는다. 두 Release 라이브러리는 Qt 동적 라이브러리에 연결되지 않았다. 설치 소비자는 `build/` 내부의 별도 설치본을 사용했으며 `~/.local` 설치본을 교체하지 않았다. 각 수치는 같은 기능을 여러 구성에서 반복한 검사 건수다.

## 남은 한계

GLB의 큐빅 베이크 오차는 유한한 검사 시점의 관측치이며 모든 시각의 오차 보증이 아니다. STEP 근사를 선택한 시간 구간에서는 원본과 다를 수 있다. 본체 `AnimationPlayer`는 모프 적용을 자동으로 등록하지 않으므로 호스트가 재생 시각에 공용 적용 함수를 호출해야 한다. FBX 원본 편집 곡선·제약·컨트롤 리그를 복원하지 않으며 FBX 기본 모프 병합 정책과 `PerMesh`의 차이를 호출자가 선택해야 한다.

사용자 지시에 따라 CC5·Blender·Unreal 및 별도 사용자용 앱은 실행하지 않았다. 실제 앱 호환성, 제작용 MetaHuman DNA 전체의 평가와 제작용 시각 품질은 이 기록의 검증 범위가 아니다. Windows·Linux 실제 빌드와 실행도 이 기록에는 없다. 전체 남은 과제는 [NSCharacter 목표](NSCharacter.md)의 남은 구현과 검증을 따른다.
