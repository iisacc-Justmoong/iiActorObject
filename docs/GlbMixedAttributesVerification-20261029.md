# 혼합된 GLB 메시 속성 검증 기록 — 2026-10-29

## 변경 내용

한 메시의 재질별 프리미티브가 서로 다른 법선이나 UV 세트를 갖는 경우 기존 가져오기는 전체 메시를 거부했다. 본체 GLB 가져오기는 이제 같은 위치·스킨·모프 접근자의 원본 점을 공유하면서 각 부분의 제공된 속성을 유지한다. 법선이 없는 면은 분리된 평면 법선을 만들고, 같은 메시의 다른 부분에 있는 UV 세트가 없으면 사용하지 않는 기본 좌표를 채운다. 두 보정은 경고한다.

각 부분의 기본색·노멀 텍스처가 요구하는 UV 세트는 그 부분에 실제로 있어야 한다. 다른 부분의 UV나 생성된 기본 좌표가 이를 대신하지 않는다. 해당 조건과 정점·모프 법선 작업량 제한을 위반하면 새 본체 에셋을 등록하지 않는다. 본체가 자료와 변환을 소유하고 NSCharacter는 결과를 참조한다.

## 자동 검사

- 서로 다른 법선·UV 구성을 가진 두 스킨 프리미티브를 독립적으로 구성했다. 프리미티브 순서, UV 일부 또는 전체 부재, 공유 원본 점·본 가중치, 원본 모프 법선과 생성된 모프 법선, 재질별 면을 검사한다. 기존 동작의 거부를 먼저 재현했다.
- 원본 탄젠트가 한 부분에만 있는 경우, 반사된 기준 변환의 면 방향, 모프가 면을 접어 퇴화시키는 경우, 기본색·노멀 텍스처가 없는 UV를 요구하는 경우와 자원 예산 초과를 검사한다. 가져온 메시의 편집·undo와 네이티브 프로젝트 복원도 확인한다.
- 독립 GLB 판독기는 원본과 다시 내보낸 파일의 프리미티브, 스킨, UV, 모프 위치와 법선을 확인한다. 코어 전용·NSCharacter 포함·ASan/UBSan 구성에서 관련 테스트 17개씩 통과했으며 누수 검사는 비활성화했다.
- `build/` 아래에 스테이징한 코어 전용 및 NSCharacter 포함 SDK를 사용하는 각각의 별도 소비자로 가져오기를 검사했다. 사용자 설치 위치는 변경하지 않았다.

## 한계

없는 UV를 기본값으로 채웠으므로 내보낸 GLB에서 원본의 UV 부재 자체가 보존되는 것은 아니다. 섞인 법선의 생성 모프 델타는 가져올 때 계산되므로 이후 표면 편집에 따라 재계산이 필요할 수 있다. 결과는 합성 자료와 독립 파일 판독에 대한 근거이며, 실제 CC5·Blender·Unreal 앱은 사용자 지시에 따라 실행하지 않았다. 제작용 MetaHuman 캐릭터와 모든 GLB 재질·확장을 지원한다는 뜻은 아니다.
