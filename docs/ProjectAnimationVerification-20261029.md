# 프로젝트 애니메이션 저장·재연결 검증: 2026-10-29

이 기록은 편집 프로젝트 버전 27의 애니메이션 저장과 재연결에 대한 특정 소스 상태의 검사 결과이다. 전체 캐릭터 제작 목표가 완료되었다는 뜻은 아니다.

## 확인한 동작

- 본·스칼라 키, 메시별 모프 대응, 원본 시작 시각과 필수 변형 바인드를 여러 클립과 함께 저장하고 새 엔진에서 복원했다. 프로젝트 전체 재저장 시 클립과 리그를 함께 전달한다.
- GLB에서 변환한 모션을 FBX로 출력하고 메시별로 다시 읽어 프로젝트에 저장한 뒤, 복원된 인스턴스의 본과 모프에 적용했다.
- 메시 형상 편집으로 새 에셋이 만들어졌을 때 동일한 골격·바인드와 메시·모프 이름을 확인하고 클립을 명시적으로 재연결했다. 다른 본 바인드, 메시·모프 이름, 삭제된 원본 및 중복 대응은 거부했다. 같은 회전을 표현하는 쿼터니언 부호 차이는 허용했다.
- 기존 프로젝트 버전 1~8의 고정 fixture와 이전 버전 선택·손상 입력을 검사했다. 별도 Python 판독은 버전 27의 헤더·CRC와 클립 자료를 읽고 체크섬을 다시 계산한 7가지 손상 자료가 거부되는지 확인했다. 실패 후 기존 엔진 자원과 다음 ID를 확인했다.

## 구성과 결과

모든 항목은 macOS arm64의 C++ 자동 검사 및 파일 형식 검사이며 실제 앱 실행은 포함하지 않는다.

| 구성 | 결과 |
| --- | --- |
| Release, NSCharacter 제외: 프로젝트·애니메이션 관련 회귀 | 71/71 통과 |
| Release, NSCharacter 포함: 같은 범위와 큰 인체 GLB 베이크 | 73/73 통과 |
| Debug, NSCharacter 포함, AddressSanitizer·UndefinedBehaviorSanitizer | 26/26 통과 |
| 별도 설치 경로의 SDK 소비자: 코어 전용 및 NSCharacter 포함의 GLB·FBX 각 2건 | 4/4 통과 |

공개 프로젝트 결과 구조 변경 후 과거 테스트 바이너리를 새 라이브러리와 섞어 실행했을 때 기존 무결성 검사 9건이 실패했다. 두 Release 구성 전체와 소비자를 새 헤더에 맞춰 다시 빌드한 후 위 회귀 검사는 모두 통과했다. 이 변경의 C++ 소비자는 일치하는 헤더와 라이브러리로 다시 빌드해야 한다. AddressSanitizer의 누수 검사는 비활성화했으므로 누수 검증은 포함하지 않는다.

설치 소비자는 `build/` 내부의 별도 설치본을 사용했으며 `~/.local`은 교체하지 않았다. 위 수치는 같은 기능을 여러 구성에서 반복한 검사 건수다.

## 한계

현재 에셋이 바뀐 경우 자동 재타깃하지 않는다. 안전한 명시적 재연결은 골격의 위치·스케일·계층과 연결된 메시·모프 순서가 유지될 때만 가능하다. 골격 바인드가 변경된 캐릭터는 별도 리타깃이 필요하다. 프로젝트는 표본화된 본체 클립을 보존하며 원본 FBX·GLB의 제약, 편집 곡선, 큐빅 접선, STEP 근사 보고서를 저장하지 않는다.

사용자 지시에 따라 CC5·Blender·Unreal 등 실제 앱은 실행하지 않았다. 해당 앱의 가져오기 결과, 제작용 MetaHuman DNA 전체와 최종 시각 품질, Windows·Linux 실제 빌드는 이 기록에 포함되지 않는다. 전체 남은 범위는 [NSCharacter 목표](NSCharacter.md)를 따른다.
