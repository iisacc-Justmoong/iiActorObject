# FBX 이미지 해석 검증 기록

2026-10-28 macOS arm64에서 [FBX 이미지 해석 계약](FbxImageResolution.md)의 변경을 확인했다. 이 기록은 캐릭터 생성·편집 전체 또는 세 외부 앱의 호환성 완료를 뜻하지 않는다.

## 구현과 검사 범위

- 외부 기본색·노멀 PNG의 호스트 공급, 공유 Video의 중복 제거, 원본 PNG 바이트와 UV 연결, FBX 및 네이티브 프로젝트 재입력을 검사했다. 해석기 미지정·자료 누락·신뢰하지 않는 경로, 잘못된 MIME·PNG·진단·요청 수·바이트 예산, 예외 발생 시 기존 엔진의 자산 보존도 검사했다.
- 선택형 iiVisualCodec 어댑터로 외부 JPEG·TGA 및 내장 JPEG를 PNG로 변환하고 디코딩된 픽셀을 입력 디코딩 결과와 비교했다. 외부 PNG 원본 보존, 변환 경고, 원본·픽셀·출력 한도, 외부 소스 미호출도 검사했다. 변환 전 원본 바이트는 에셋에 남지 않는다.
- 독립 Python 파서가 변환 결과의 GLB image·texture·기본색·노멀 연결과 FBX Video·Texture·재질 연결을 확인했다. 양쪽 PNG 바이트가 같으며 PNG 청크 CRC와 압축 데이터가 유효한지 검사했다.
- NSCharacter가 포함된 일반 구성의 관련 이미지·FBX·프로젝트 자동 회귀 55개와 NSCharacter를 끈 코어 전용 구성의 관련 자동 회귀 57개가 각각 통과했다. 후자의 57개에는 코덱 어댑터의 5개 검사와 위 독립 파서 검사가 포함된다. 두 집합은 서로 중복된다.
- 정적 AddressSanitizer·UndefinedBehaviorSanitizer 구성에서 코어 해석기 검사 4개가 통과했다. 이 머신의 AddressSanitizer는 누수 검출을 지원하지 않아 `detect_leaks=0`으로 실행했으며 누수 검사는 수행하지 않았다. 어댑터의 모든 서드파티 코드를 계측한 검사는 아니다.
- 별도 설치 스테이징의 C++23 소비자 3개가 통과했다. 코어 전용 패키지는 코덱 컴포넌트 없이, 선택형 코덱은 해당 컴포넌트만 링크해 사용했다. 일반 구성의 소비자는 `NSCharacter::importFbx`를 호출하고 엔진 종료 뒤 캐릭터 참조가 무효화되는지 검사했다. 스테이징은 프로젝트 `build/` 아래이며 `~/.local`에 설치하지 않았다.
- 코어 동적 라이브러리와 선택형 코덱 소비자의 직접 동적 의존성을 확인했으며 Qt는 나타나지 않았다. 코덱 소비자에는 macOS CoreGraphics·CoreFoundation 및 시스템 라이브러리가 포함된다. 정적 서드파티 라이브러리는 별도 코덱 의존성이다.

이 머신의 기존 iiVisualCodec 정적 설치본은 JPEG ABI 80을 기대한다. 초기 자동 탐색의 ABI 62와는 호환되지 않아 검사에서 JPEG 라이브러리를 ABI 80인 jpeg-turbo로 지정했다. 누수 검출 옵션과 JPEG ABI 오류는 수정 후의 최종 통과 집계에 포함하지 않는다.

## 제한과 후속 작업

검사는 합성 FBX와 이미지, 네이티브 코드 및 독립 형식 파서에 한정한다. 사용자 지시에 따라 CC5·Blender·Unreal 애플리케이션은 실행하지 않았다. 실제 제작용 자료와 외부 앱의 셰이더·색상·가져오기 동작, Windows·Linux 빌드, 다른 코덱 빌드의 지원 형식은 이번 결과로 확인하지 않았다. 피부·얼굴·의상의 제작 품질, 템플릿과 DNA의 넓은 범위, 표면 편집 및 리그 관련 남은 작업은 [NSCharacter 작업 목록](NSCharacter.md)을 따른다.
