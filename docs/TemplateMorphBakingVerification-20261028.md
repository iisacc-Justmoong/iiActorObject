# 템플릿 부속 모프 검사 기록 — 2026-10-28

## 검사 범위

앱을 실행하지 않고 본체 C++23 생성·샘플 결과와 별도 Python FBX 7.4/GLB 파서를 검사했다. 수치는 이 저장소의 CC0 MakeHuman 본체·얼굴 자료와 지정된 입력에서 얻은 결과다. 다른 자산이나 앱에서의 시각 품질·호환성을 보증하지 않는다.

## 몸과 의상

형상 기준 `rise=0.5`에서 `rise=1`까지 변하는 합성 몸과 의상에 `body_rise` 모프를 생성했다. 본체와 의상 양쪽의 가시점은 Z 방향으로 0.01 이동한다. 독립 파서는 FBX의 몸 7점(숨은 보조점 포함)과 의상 5점, GLB의 몸 5 렌더 정점과 의상 5 렌더 정점에 동일한 모프 채널과 변위가 있는지 확인했다.

별도의 네 메시 합성 그래프는 몸·눈·치아·의상 전체의 기준 위치에 베이크된 변위를 더한 결과를 직접 평가한 목표 위치와 비교한다. 렌더 전용 메시, 여러 입력의 합산, 기존 이름 거부와 명시 교체, 변위 생략 임계값, 자원 초과 시 미등록, 엔진 소멸 시 참조 만료도 검사한다.

본체 리그 세션으로 같은 정규화 가중치를 네 메시의 채널에 적용하고, 두 개의 named 채널을 혼합할 때의 렌더 위치를 검사한다. 기존 포즈를 보존하며, 잘못된 범위와 채널·메시 목록 불일치를 거부하고, 서로 다른 메시 이름으로의 리그 재연결을 거부한다.

## 인체 얼굴 부속

`model/head/head-scale-horiz-decr-incr`의 기준 0.4와 목표 0.8을 `head_width` 채널로 베이크했다. 네 메시 전체에서 10,488개의 작성용 점 변위가 기록되었고, 모든 점에 기준 위치와 베이크 변위를 적용해 직접 평가한 목표 형상과 비교한 최대 오차는 0이었다. 목표 평가에서 기준 로컬 bind 변환이 바뀐 관절은 63개다. 이는 외부 모프만으로는 관절 변경을 재현하지 못한다는 사실을 보여 준다.

본체에서 생성한 액터의 기준 포즈에서 리그의 `head_width=1`을 적용했을 때 네 메시, 20,569 렌더 정점의 목표 형상 대비 최대 거리는 약 `6.72e-16`이었다. 이 값은 다른 포즈에서 바뀐 관절 역바인드까지 정확하다는 의미는 아니다.

독립 FBX 파서는 몸 `OBJ` 5,458점, `Eyes` 1,064점, `Teeth` 3,766점, `Tongue` 200점의 같은 이름 채널과 유효한 변위를 확인했다. GLB에서는 같은 네 메시의 각각 4,498, 1,076, 4,706, 264개 렌더 정점에 채널이 기록되었다. 작성용 점과 UV 분할 렌더 정점 수는 같을 필요가 없다. 이 파일은 이름이 같은 개별 메시 모프를 담는다. 실제 호스트에서 자동 동기화되는지에 대한 검사는 수행하지 않았다.

## 재현과 제한

`iiActorObject.template_adapt`의 합성 검사, 인체 자료 검사 및 독립 형식 검사와 `tests/VerifyFollowerMorphs.py`를 사용한다. 템플릿·리그 전사·스킨·문서·FBX 관련 회귀 검사는 표준 구성 115개와 NSCharacter를 끈 코어 구성 114개가 통과했다. build 내부에 별도로 설치한 표준·코어·VisualCodec 소비자 세 종류도 새 공개 API를 컴파일하고 통과했다. ASan·UBSan 구성의 템플릿 검사 7개도 통과했다. 이 macOS 실행에서는 leak 검출을 켜지 않았다. CMake의 `IIACTOROBJECT_VALIDATE_APPLICATION_EXECUTION`은 OFF다. 모프 가중치 0과 1에서만 샘플 형상을 확정한다. 비선형 중간 상태, 여러 모프의 상호작용, 바뀐 관절과 응용 프로그램의 제어 UI는 별도의 문제다.
