# GLB 원본 점 식별 검증 기록

2026-10-28 macOS arm64에서 [GLB 메시의 원본 점 식별 정보](GlbPointIdentity.md)를 네이티브 테스트와 SDK 가져오기 코드와 별개인 Python 파일 판독기로 확인했다. 이 기록은 실제 앱의 호환성이나 MetaHuman 전체 구현의 증거가 아니다.

- UV·탄젠트·재질 경계에 분리된 표시 정점을 같은 제어점으로 다시 연결하고, 숨겨지거나 사용되지 않는 점의 위치·스킨·논리 모프와 빈 스킨 행을 복원했다. 제어점 1개를 이동하면 이음새 양쪽의 표시 정점이 함께 움직였다. 다중 재질과 65,535를 넘는 ID 65,536·65,537도 확인했다.
- 독립 GLB 판독기로 표준 속성과 보조 뷰를 읽은 뒤 표시 인스턴스의 위치·스킨·모프를 일관되게 바꾸거나 한쪽만 바꾸었다. 일관된 변경은 유지하고 충돌한 변경은 보조 자료를 적용하지 않은 표준 점으로 유지하면서 경고하는지 확인했다. 프리미티브가 사용하지 않는 오래된 중복 행은 표시 점과 충돌시키지 않았다. 잘못된 ID·서명·버전·크기, 빠진 속성, 바뀐 모프·관절 이름과 노드 이동·반사도 확인했다.
- CC0 MakeHuman의 인체 시료 하나에 모프 1개와 노멀 맵을 연결했다. FBX에서 GLB로 변환하고 본체에 다시 읽었을 때 원본 점 19,158개와 각 좌표의 절대 오차가 0.00002보다 작은지 확인했다. 독립 판독기는 GLB 삼각형 코너 80,268개의 점 번호·탄젠트·가중치와 163개 관절을 원본 FBX와 대조했다.
- NSCharacter가 포함된 일반 구성의 관련 회귀 검사 16개, 별도 점·재질 중심 검사 5개와 코어 전용 구성의 관련 검사 19개가 통과했다. 검사 묶음에는 중복이 있다. 추가된 일관된 모프 편집 검사도 두 구성에서 각각 통과했다.
- AddressSanitizer·UndefinedBehaviorSanitizer 구성에서 입력 검증, 대형 점 번호, 외부 편집·충돌 판독의 선별 검사 3개가 통과했다. 정의되지 않은 동작 발견 시 즉시 중단하도록 실행했으며 macOS의 누수 검출은 끈 상태였다. 연결된 모든 의존성이 계측되었다는 증거는 아니다.
- `build/`에 각각 설치한 일반·코어 단독 라이브러리를 쓰는 외부 C++23 소비자 검사 2개가 통과했다. 설치 단계의 라이브러리가 해당 빌드 결과와 바이트 단위로 같은지 확인했고, 두 macOS 라이브러리의 동적 의존성에는 Qt가 없다. 사용자 홈 설치본을 교체하지 않았다.

GLB 표준 데이터는 원래 폴리곤과 숨김 면, 원본 layout·UV·법선 ID, 분리된 동일 이름 모프 기록을 복원하지 않는다. 외부 앱이 선택적 점 식별 속성이나 메타데이터를 제거할 수도 있다. 사용자 지시에 따라 CC5·Blender·Unreal을 실행하지 않았고 실제 앱에서의 읽기·편집 결과와 화면 품질, Windows·Linux는 검사하지 않았다.
