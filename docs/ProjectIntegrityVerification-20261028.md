# 프로젝트 복원 무결성 검증 — 2026-10-28

[프로젝트 형식](Object3DProject.md)의 계층 재계산과 스냅샷 대조에 관한 기록이다. 캐릭터 엔진의 전체 완성을 뜻하지 않는다.

## 문제와 수정

기존 대조는 프로젝트 버전 14의 자산 필드만 비교했다. 버전 15의 기준 자세 순서 및 버전 16의 UV 세트·머티리얼 선택은 저장하고 읽었지만, 복원한 템플릿과 저장 스냅샷이 다른지는 검사하지 않았다. 체크섬과 양쪽 자료가 모두 유효한 경우에도 이후 레이어 재계산에서 값이 달라질 수 있었다.

복원된 과거 버전의 기본값을 포함하여 현재 형식의 자산 필드 전체를 비교하도록 수정했다. 추가 UV 보정은 비활성 레이어를 포함해 세트와 좌표 ID의 중복·범위를 확인한다. 검사에 실패한 복원은 기존 자원과 편집 이력 및 다음 ID를 보존한다. 형식 버전이나 공개 API는 이번 수정에서 변경하지 않았다.

## 확인한 범위

- 수정 전 체크섬이 유효한 프로젝트의 UV 세트 이름·좌표·layout 대응·머티리얼의 세트 선택·기준 자세 순서를 각각 바꾸었을 때 다섯 사례 모두 잘못 받아들이는 것을 재현했다.
- 대조 수정 후에도 비활성 레이어의 중복 UV 좌표와 중복 세트 보정이 받아들여지는 두 사례를 별도로 재현하고, 두 종류를 거부하도록 수정했다. 범위 밖 세트와 좌표 ID도 검사한다.
- 최종 7개 시험은 작성용 토폴로지뿐 아니라 렌더 메시에도 적용 가능한 사례를 반복한다. 정상 프로젝트는 복원되고, 조작한 입력은 예상한 검증 경로에서 거부되며 이미 존재하던 엔진 자원과 ID가 유지된다. 제작용 데이터에 대한 포괄적인 안전성 증거는 아니다.
- macOS 일반 구성에서 프로젝트·기준 자세·UV·계층·DNA 관련 회귀 67개와 독립 형식 검사가 포함된 묶음이 통과했다. NSCharacter를 끈 코어 전용 구성은 해당 기능의 회귀 63개가 통과했다. 이후 확대된 최종 무결성 사례 7개는 두 구성에서 각각 다시 통과했다.
- 별도 스테이징한 일반·코어 전용 설치 패키지의 자세·UV·DNA 소비자 검사는 각각 3개가 통과했다. Qt 동적 의존성은 두 macOS 공유 라이브러리의 직접 의존성에서 발견되지 않았다.
- 주소 및 정의되지 않은 동작 검사기(`-fsanitize=address,undefined`)로 빌드한 구성에서 최종 무결성 사례 7개가 통과했다.

사용자 지시에 따라 CC5·Blender·Unreal과 SDK 사용자 앱을 실행하지 않았다. 이 결과는 해당 앱에서의 호환성이나 제작용 MetaHuman·인체 외형 품질을 증명하지 않는다.
