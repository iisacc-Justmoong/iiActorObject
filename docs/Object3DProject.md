# 캐릭터 편집 프로젝트 저장과 복원

## 목적과 소유권

`Object3DProject`는 생성·상세 편집 작업을 저장한 뒤 이어서 편집하기 위한 본체 기능이다. 저장·복원과 모든 장기 자료는 `iiActorObject`에 있다. NSCharacter의 `exportProject`·`importProject`는 본체 함수를 호출하고 참조 핸들만 보유한다. `CharacterEditor::session()`도 본체 편집 세션의 참조이다. 엔진 소멸 시 복원한 에셋·편집기·리그 참조가 만료된다.

FBX·GLB·DNA는 계산된 결과의 교환에 사용하고, `.ii3dproject`는 SDK에서 파라미터·보정 계층·이력을 이어서 편집하는 데 사용한다. CC5·Blender·Unreal은 자체 프로젝트 파일을 직접 읽지 않는다. 외부 앱으로 보낼 결과는 복원한 본체 에셋에서 FBX·GLB·DNA로 출력한다.

## 저장하는 자료

- 원본 제어점·스킨·분리 UV와 법선·원본 폴리곤·숨김 면·머티리얼·모프 target ID이다. 사용하지 않는 원본 자료와 명시적 모프 법선도 보존한다.
- 토폴로지가 없는 메시의 렌더 정점·삼각형·법선·스킨·모프·UV와 삼각형별 머티리얼이다.
- 중립 템플릿, 모든 희소 타깃·범위, 관절 앵커와 현재 파라미터이다.
- 보정 계층의 ID·이름·순서·활성 상태·강도·실제 보정 자료이다. 관절 스케일 델타와 원본 본 ID를 유지하는 부모 변경도 포함한다.
- undo·redo의 전체 보존 구간, 현재 커서, 이력 제한, revision과 다음 계층 ID이다. 템플릿 분리 전후의 혼합 이력도 보관한다.
- 호출자가 선택한 DNA·포즈·자세 보정·템플릿 모프·점진 모프 리그의 프로그램과 바인딩 에셋·관절 대응이다. 여러 LOD 리그는 같은 원본 DNA를 공유하여 저장한다. 템플릿 모프 리그는 기준 입력과 채널별 원본 입력·끝점·메시·변경 관절의 출처를 저장하며, 살아 있는 원본 템플릿도 함께 보관한다.

작성용 메시의 렌더 캐시는 저장하지 않고 원본에서 재생성한다. 다만 **기존 삼각형 연결은 원본 layout의 일부로 저장한다.** 편집된 점에서 다시 대각선을 선택하면 이전 조형·모프의 연결이 달라지기 때문이다. `MeshTopologyLayout::restore`는 폴리곤 경계·삼각형 방향·내부 변의 짝·교차하지 않는 대각선과 face 대응을 검사한다. 현재 위치에서의 렌더 삼각형 유효성은 기존 에셋 검사도 거친다. 공유하던 불변 layout은 복원 후에도 공유한다.

에셋·템플릿·계층 상태·보정 자료는 참조 그래프로 기록하여 이력마다 같은 자료를 반복하지 않는다. 원본 DNA와 편집 스냅샷은 별도 자료이다. 편집한 스냅샷을 원본 DNA로 오인하지 않으며, 프로젝트 복원 후에도 `exportObject3DDna`의 명시적 모프 법선 손실 정책이 적용된다.

## 사용

```cpp
#include <iiActorObject/Object3DProject.h>

auto bytes = iiActorObject::exportObject3DProject(editor, selectedRigs);
// 호스트가 bytes를 파일·문서 저장소에 저장한다.
auto restored = iiActorObject::importObject3DProject(engine.reference(), bytes);
restored.editor.get().setTemplateValues(values);
auto result = restored.editor.get().object();
```

NSCharacter는 `exportProject(characterEditor, selectedRigs)`와 `importProject(engine.reference(), bytes)`를 제공한다. 반환한 `CharacterProject::editor`는 기존 파라미터·계층·undo API를 사용한다.

프로젝트 함수는 바이트열을 읽고 반환하며 파일 경로를 열거나 외부 자료를 다운로드하지 않는다. 파일의 원자적 저장·버전 관리와 문서 UI는 호스트의 책임이다. 복원한 리그는 저장 당시의 불변 에셋에 연결된다. 이후 메시·중립 골격을 편집하면 `cloneFor(newObject, rig.jointMapping())`로 새 스냅샷에 다시 연결하거나 [편집 리그 참조](EditorRigFollow.md)를 사용한다. 리그 평가에는 매번 전체 입력 제어값을 전달한다.

## 형식과 실패 처리

버전 25는 작성된 control-point 표면 연결의 선택적 오프셋 기저를 저장한다. 회전·스케일로 적응한 부속의 축별 추종과 이력을 복원하며, 기저가 없는 프로젝트는 다른 자료가 요구하는 기존 버전을 선택한다. 이전 버전의 기저는 오브젝트 축이다. 공개 `Object3DTemplateDefinition` 구조가 바뀌었으므로 C++ 소비자는 일치하는 헤더와 라이브러리로 다시 빌드해야 한다. 기존 `SurfaceBinding`의 크기와 기존 표면 연결 함수는 유지한다.

버전 26은 선택한 [관절 자세 보정 리그](PoseCorrectives.md)의 프로그램과 에셋·본 대응을 저장한다. 동일한 프로그램의 여러 세션은 같은 자료를 참조하며, 복원할 때 각 에셋의 보정 모프와 본 대응을 다시 검사한다. 이 리그를 포함하지 않은 프로젝트는 다른 자료에 필요한 기존 버전을 계속 선택한다. 액터 인스턴스와 자동 실행 컴포넌트는 저장하지 않으므로 복원한 리그를 인스턴스에 다시 부착한다.

버전 27은 명시적으로 전달한 [애니메이션 클립과 메시별 모프 대응](ProjectAnimation.md)을 저장한다. 클립을 선택하지 않으면 기존 버전 선택을 유지한다. 복원한 프로젝트 전체를 재저장하는 오버로드는 리그와 클립을 함께 보존한다.

버전 28은 보존된 이력에서 에셋과 이름 있는 선택이 동시에 바뀌는 [선택 이전](SelectionTransfer.md) 단계를 허용한다. 버전 27과 같은 필드 배치를 사용하고 전이 규칙을 확장한다. 복원은 선택 이름·각 에셋에 대한 선택 크기와 값·대상 단계의 템플릿 분리를 검사한다. 그런 단계가 없으면 애니메이션 등 다른 자료에 필요한 이전 버전을 선택한다.

버전 29는 에셋과 편집 이력의 [재질 알파 방식·임계값·양면 설정](MaterialSurface.md)을 저장한다. 모든 재질의 설정이 기본값인 프로젝트는 다른 자료에 필요한 기존 버전을 선택한다. 이전 버전은 기존 자동 투명 처리로 읽는다.

버전 30은 [다중 후손 중심을 향하는 기준 자세](PoseReference.md)의 추가 본 ID를 에셋과 편집 상태·이력에 저장한다. 다중 후손 제약이 없으면 재질 등 다른 자료에 필요한 기존 버전을 선택한다.

버전 31은 선택한 [점진 모프 리그](ProgressiveMorphRig.md)의 채널·기본값·키와 대상 모프 이름을 에셋 연결과 함께 보관한다. 이 리그가 없으면 다른 자료에 필요한 기존 버전을 선택한다. 복원할 때 대상 에셋의 타깃을 확인한다.

버전 32는 템플릿의 [명시적 접지 점 집합](HumanMorphology.md)을 보관한다. 현재 상태 또는 보존된 이력의 템플릿에 이 집합이 있을 때 작성한다. 집합이 없는 프로젝트는 필요한 기존 버전을 선택하며, 버전 7~31의 접지는 표시 점을 기준으로 복원한다.

버전 33은 추종 표면 제거로 메시 슬롯과 이름 있는 점 선택이 함께 바뀐 이력에 이전 슬롯에서 새 슬롯으로의 대응을 보관한다. 복원 시 이전과 이후 원본 점 연결과 모든 선택 행의 이름·가중치를 검증하며 제거된 슬롯의 선택 행만 없어질 수 있다. 이 대응이 보존 이력에 없으면 다른 자료에 필요한 기존 버전을 선택한다. 이력의 시작이 잘려 대응의 이전 상태가 빠진 경우 시작 상태에는 대응을 저장하지 않는다. 버전 32 이하만 지원하는 기존 라이브러리는 버전 33을 읽지 못하므로 소비자를 새 라이브러리로 갱신해야 한다.

버전 34는 추종 표면 삽입에 따라 선택된 기존 메시의 슬롯이 이동한 이력을 보관한다. 기존 버전 33의 대응 자료 구조를 쓰지만, 중간에 새 슬롯이 들어갈 수 있으며 기존 메시의 상대 순서·원본 점과 선택 가중치는 그대로 유지되어야 한다. 삽입 때문에 선택 대응이 바뀐 이력이 없으면 필요한 기존 버전을 선택한다. 버전 33 이하만 지원하는 라이브러리는 버전 34를 읽지 못한다.

버전 35는 하나의 편집 단계에서 표면을 제거하고 다른 표면을 추가하여 이름 있는 선택의 슬롯이나 행이 바뀐 이력을 보관한다. 버전 33·34의 대응 자료 구조를 사용하되, 제거된 행과 새로 삽입된 슬롯을 모두 허용한다. 복원은 남은 메시의 이름·상대 순서·원본 점 연결과 선택 이름·가중치를 검사하며 중복·역순·범위 밖 대응을 거부한다. 이런 이력이 없으면 필요한 기존 버전을 선택한다. 버전 34 이하만 지원하는 라이브러리는 버전 35를 읽지 못한다.

버전 24는 현재 자산 또는 보존 이력의 [GLB 원본 탄젠트와 모프 탄젠트](GlbAuthoredTangents.md)를 저장한다. 기준 형상·모프 및 재질 연결과 스냅샷의 공유 관계를 함께 보존한다. 이 자료가 없으면 다른 자료에 필요한 기존 버전을 선택하며, 버전 1~23에는 GLB 탄젠트 스냅샷이 없다.

버전 23은 현재 자산 또는 보존된 이력의 [메시별 기본 모프 값](DefaultMorphWeights.md)을 저장한다. 값이 없으면 기존 버전 선택을 유지한다. 버전 1~22의 누락된 기본값은 0이다.

프로젝트 헤더는 24바이트이며 현재 입력은 버전 1~35를 지원한다. 8바이트 `iiAOPRJ\0`, little-endian uint32 버전, uint64 payload 길이, uint32 CRC-32 순서이다. 버전 2의 [표면 연결](SkinSurface.md)에 이어 버전 3은 [레이어 점 마스크](MeshPainting.md)의 공유 사전과 참조를 추가한다. 버전 4는 [골격 상세 편집](SkeletonEditing.md)의 관절 스케일과 부모 override를 추가하였다. 버전 5는 [의미 조절](TemplateControls.md)의 항목·곡선·복합 드라이버를 추가하며 버전 1·2·3·4 입력도 계속 읽는다. 버전 6은 [불변 PNG 자원과 원본 점 대응](FaceAssets.md)을 추가하며 버전 1~5 입력을 지원한다. 이전 자료의 이미지 목록은 비어 있고 기존 표면 연결은 삼각형 방식으로 복원한다. 버전 7은 [형상 생성의 접지 정의](HumanMorphology.md)를 추가하고 버전 1~6 입력을 지원한다. 이전 버전의 접지는 비활성 상태이다. 버전 8은 [회전 포즈 프로그램과 리그](FacePoseRig.md)의 종류·자료와 템플릿의 선택 프로그램을 추가하고 버전 1~7을 지원한다. 포즈 프로그램은 DNA를 제외한 코어에서도 복원한다. 버전 9는 [자동 표면 맞춤](AutomaticSurfaceFitting.md)의 설정·장애물·이동 비율과 한도를 추가한다. 보존된 이력의 템플릿에 해당 설정이 있으면 버전 9를 작성하고, 평가 계층과 설정이 모두 없는 프로젝트는 기존 버전 8로 작성한다. 비활성 설정도 보존 대상이다. 버전 10은 [계산된 표면 위의 평가 계층](EvaluatedEditLayers.md)을 추가한다. 보존 이력에 해당 계층이 있으면 버전 10을 우선 작성하며, 알려지지 않은 평가 종류는 거부한다. 이전 버전 계층은 기존 누적 방식으로 복원한다. 버전 11은 [충돌 보정의 형상 정리](SurfaceFairing.md) 설정을 추가하며 종전 변위 목적함수로 복원한다. 버전 12는 최대 변 길이 왜곡을 제한하는 새 정책을 명시한다. 비기본 형상 정리 설정이 있고 보존 이력의 어느 규칙이든 새 정책을 사용하면 비활성·기본 규칙도 포함하여 버전 12를 작성한다. 모두 종전 정책이면 버전 11을 유지한다. 버전 1~10의 형상 정리는 비활성이며 새 정책의 기본값으로 복원한다. 이렇게 정책을 구분하여 저장된 형상과 이력을 다른 알고리즘으로 재해석하지 않는다. 버전 1~4의 템플릿은 조절과 드라이버가 없는 기존 프로그램으로 복원한다. CRC는 전송·저장 오류를 찾는 검사이며 작성자 인증 수단이 아니다. payload의 정수·개수는 uint64, 수치는 IEEE float64, bool은 0 또는 1의 한 바이트이다. 문자열은 바이트 길이와 원문을 보관한다. 프로세스 포인터·절대 파일 경로의 해석·실행 코드·UI callback을 기록하지 않는다.

`Object3DProjectOptions`의 기본 제한은 파일 256 MiB, 디코딩 자료 512 MiB, 집합 원소 1,600만 개, 개별 문자열 4,096바이트, 에셋 4,096개, DNA reader 메모리 1 GiB이다. 디코딩 예산은 구조·문자열·바이트 버퍼의 할당에 대한 제한이며 렌더 캐시·검증 임시 자료까지 합친 전체 프로세스 메모리 상한은 아니다. 엔진의 자원 개수 제한도 적용한다.

프로젝트는 템플릿 64개, 선택 리그 256개, 각 리그 프로그램 테이블 256개까지 허용한다. 이 고정 상한은 내보내기와 가져오기 모두에 적용하여 복원할 수 없는 파일을 생성하지 않는다.

잘린 파일, 알 수 없는 버전, 길이·CRC 불일치, 비유한 수치, 범위 밖 참조, 중복 sparse ID, 잘못된 계층·파라미터·삼각형 연결을 거부한다. 비활성 계층도 ID·수치·부모 범위·이름·쿼터니언 입력 검사를 거친다. 부모·스케일 보정은 앞선 계층에 의존할 수 있으므로 활성 계층을 순서대로 평가하고, 비활성 계층의 현재 조합에서의 활성화 가능성은 활성 변경 시 검사한다. 계층을 재계산한 결과와 저장 스냅샷을 대조하여 불일치를 거부한다. 원본 ID는 정확히 비교하며 정규화 수치의 비교에는 상대·절대 허용 오차 `1e-10`을 사용한다.

복원은 본체 엔진의 트랜잭션 경계에서 수행한다. 도중에 디코딩·검증·용량·리그 생성이 실패하면 기존 자원 맵과 다음 ID 카운터를 복원한다. 기존 편집기와 에셋을 수정하지 않는다. 한 호스트 스레드가 엔진 접근을 직렬화한다는 기존 계약을 따른다.

DNA는 고정된 native OpenRigLogic 백엔드만 복원한다. 임의 사용자 리그 드라이버의 C++ 실행 코드는 저장할 수 없으므로 조용히 제외하지 않고 내보내기를 거부한다. DNA를 끈 빌드는 일반 프로젝트를 사용할 수 있으며 DNA 프로그램이 있는 프로젝트는 거부한다.

## 검증과 남은 범위

회귀 검증은 원본 사각형·사용하지 않는 제어점·명시적 법선·현재 파라미터·계층 ID와 강도·redo·분리 이력·분기 후 편집, 렌더 메시, 엔진 수명, 뒤늦은 용량 실패의 롤백, 삼각형 재선택 방지를 포함한다. 실제 CC0 인체의 19,158개 제어점·163개 본·472개 생성 타깃을 저장하고 새로운 엔진에서 다시 편집한다.

DNA는 복원한 리그의 평가·다중 LOD와 원본 바이트 보존을 검사하고, 재저장한 편집 DNA를 SDK에 링크하지 않는 native reader로 확인한다. 별도 Python 표준 라이브러리 검사는 헤더·CRC와 손상 입력을 검사한다. CRC-32는 동일한 IEEE 다항식의 상수 조회표로 계산하여 큰 프로젝트에서 바이트별 8회 비트 계산을 반복하지 않는다. 저장 바이트와 독립 zlib 검사는 기존 규약을 따른다. 버전 8 fixture는 이전 SurfaceFitting 검증 단계의 바이너리로 생성한 2,851바이트이며 SHA-256은 `a9f2ec913ab7dc3f608aa6336ec5f2cb361094641bb213ffe73de76bedd1fb1c`이다. MetaHuman 제작 자료·의상 fitting·외형 품질은 이 프로젝트 형식의 검증과 별도의 남은 작업이다. 실제 앱 실행 검증은 현재 사용자 지시에 따라 제외한다.

[기준 자세 프로그램](PoseReference.md)을 포함하는 프로젝트는 버전 13을 작성한다. 각 에셋의 선택적 프로그램과 계층 상태의 override를 보관하고 초기 로컬 포즈 캐시는 복원 시 다시 계산한다. 보존된 undo/redo·템플릿 기본 에셋의 프로그램도 버전 선택에 포함한다. 프로그램이 없는 자료의 기존 버전 선택은 유지한다. CRC가 유효하더라도 에셋과 계층의 프로그램이 다르면 재생성 일치 검사에서 거부한다.

[리그 제어 샘플](RigControlSamples.md)의 출처가 자산 또는 보존 이력에 있고 명시적 기준 자세 순서가 없으면 버전 14를 작성한다. 제어와 맵 출력은 생성 시점의 기록이며 실행 가능한 리그를 대신하지 않는다. 출처가 없으면 기존 버전 선택을 유지한다.

명시적 기준 자세 제약 순서가 현재 에셋이나 보존된 이력에 있으면 버전 15를 작성한다. 버전 14 리그 샘플 출처와 순서를 함께 보존한다. 순서가 없는 프로젝트는 기존 버전 선택 규칙을 유지한다. 자세한 실행 순서와 실패 조건은 [기준 자세 프로그램](PoseReference.md)을 따른다.

[여러 UV 세트](MultipleUvSets.md)의 이름·좌표·layout 대응이나 머티리얼 UV 선택이 있으면 버전 16 이상으로 작성한다. UV 자료가 없는 기존 프로젝트는 다른 자료에 필요한 버전을 선택한다.

복원할 때는 입력 버전과 관계없이 누락된 과거 필드를 기본값으로 채운 후, 현재 형식의 전체 자산 필드로 재생성 결과와 저장 스냅샷을 대조한다. 따라서 명시적인 자세 순서와 UV 세트 이름·좌표·layout·머티리얼 선택도 비교한다. 추가 UV 보정의 세트 ID와 좌표 ID는 비활성 레이어를 포함하여 중복과 범위를 검사한다. CRC가 유효하더라도 이 조건을 위반하면 기존 엔진 상태를 유지하며 복원을 거부한다.

손상 입력·이전 버전·코어 전용과 설치 소비자 검사의 범위는 [복원 무결성 기록](ProjectIntegrityVerification-20261028.md)에 있다.

[명명 점 선택](NamedPointSelections.md)이 현재 상태 또는 보존된 이력에 있으면 버전 17 이상으로 선택 상태와 공유 마스크를 보관한다. 선택이 없는 프로젝트는 다른 자료에 필요한 버전을 선택한다.

[노멀 맵](NormalMaps.md) 참조·UV 선택이나 기본값이 아닌 강도가 에셋 또는 보존된 레이어에 있으면 버전 18 이상을 작성한다. 노멀 자료가 없는 프로젝트는 위의 기존 버전 선택을 유지한다. 버전 1~35를 읽고, 버전 17 점 선택과 버전 18 노멀 자료를 함께 보존한다. [기준 법선 편집](BaseNormalEditing.md)의 보정이 보존된 이력에 있으면 버전 19 이상을 작성한다. 비활성 보정도 범위·중복 ID와 정규 회전을 검사하며, 보정이 없으면 이전 버전 선택을 유지한다.

[FBX 원본 탄젠트](FbxTangents.md) 스냅샷이 현재 자산이나 보존 이력에 있으면 버전 20 이상을 작성한다. 폴리곤 코너별 기저와 기준 위치·법선·UV·토폴로지를 저장하고 이력 간에 공유한다. 편집된 상태에서도 원본을 보관하되 유효하지 않은 기저를 내보내지 않으며, 실행 취소 후 기준이 일치하면 다시 사용한다. 버전 20 자료가 없으면 다른 자료에 필요한 버전을 선택한다.

선택한 [템플릿 모프 리그](TemplateMorphBaking.md)가 있으면 버전 21을 작성한다. 채널 설정은 공유 테이블에 보관하고 각 리그의 대상 에셋과 선택적 원본 템플릿을 참조한다. 전체 기준 입력과 베이크 설정이 알려진 경우와 없는 경우를 각각 구분하며 입력 이름·기준·목표·채널명·부속 메시와 원래 변경된 관절의 ID 및 당시 이름을 보존한다. 포즈·DNA 리그 및 이전 기능과 함께 저장할 수 있다. 형식·중복·참조·입력 범위와 대상 메시의 실제 채널 일치 여부를 검사하며, 실패 시 엔진의 기존 자원과 ID를 되돌린다. 원본 템플릿이 제거된 후 저장하면 출처 데이터는 남지만 생성 프로그램은 복원할 수 없다. 모프 리그를 선택하지 않으면 다른 자료에 필요한 기존 버전 선택을 유지한다.

[듀얼 쿼터니언 스키닝](DualQuaternionSkinning.md)의 비기본 프로필이 현재 에셋, 템플릿 기본 에셋, 보존된 undo·redo 또는 레이어에 있으면 버전 22 이상을 작성한다. 선형·DQ·혼합 방식과 원본 점별 혼합값을 보관하며 토폴로지가 없으면 렌더 정점 순서이다. 이전 버전은 선형으로 복원한다. 비활성 레이어도 프로필의 방식·크기·범위를 검사하며, 잘못된 자료는 기존 엔진 상태를 보존하고 거부한다. 인스턴스의 임시 설정은 프로젝트 이력이 아니다.
